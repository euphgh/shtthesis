# 学位论文研究定位与写作指导

本文记录REMUS课题在中期报告和最终硕士学位论文中的共同研究定位、系统命名和写作原则。它是长期指导文件，不代替各阶段的具体大纲、论文正文、导师意见或实际实验记录；相关结论需要随研究进展核实和更新。

## 一、研究定位：研究关键技术，以系统验证研究成果

课题面向大规模SoC的硅前软硬件协同验证，研究可重放的多FPGA硬件仿真技术。与主要强调大规模设计部署和高速运行的多FPGA原型验证相比，课题进一步关注在多个FPGA之间保持DUT逻辑周期一致，支持全局一致暂停、分布式状态提取、状态恢复及确定性重放，使大规模设计既能运行，也能观测和调试。

REMUS是这些技术的**实现与验证载体**，而不是学位论文唯一的研究对象。学位论文应回答以下问题：

- **为何需要研究**：现有技术的能力边界在哪里，哪些问题尚未充分解决？
- **解决什么问题**：技术约束、研究目标及评价指标是什么？
- **如何解决**：方法及其设计依据、关键机制和适用条件是什么？
- **效果如何**：使用哪些实验、对照和指标证明有效性，仍有哪些限制？

系统工程的完整性能够证明方案具有实践可行性，但开发工作量不等同于学术贡献的大小。论文既不应写成REMUS的操作手册，也不应忽略支撑技术和端到端系统实验。

## 二、系统名称与学位论文题目

| 对象 | 约定 |
| --- | --- |
| 课题组已有的单FPGA仿真系统 | **REMU**（Replay EMUlation） |
| 当前多FPGA仿真系统 | **REMUS**（Replay EMUlation System） |
| 开题阶段的工作名称 | **SMART**（Scalable Multi-FPGA Automated Replayable Technology） |
| 学位论文题目（暂定） | **确定性可重放的多FPGA硬件仿真关键技术研究与实现** |

- REMUS作为系统名称，S取**System**。Scalability仍是研究要求，但不必强行体现在缩写中。
- 学位论文题目突出研究对象和关键技术，不必采用“REMUS系统的设计与实现”或英文系统论文的“REMUS: ...”格式。
- 学位论文使用中文撰写；REMUS、REMU等专有名称可以保留英文缩写。
- 开题报告中的SMART具有历史版本意义。后续正式稿优先使用REMUS，但**未经明确要求不要批量替换既有开题文件、中期大纲和PPT中的SMART**。需要过渡时，可在首次介绍REMUS时说明其与开题阶段SMART的关系。
- 题目为当前写作方案而非最终批准题目；具体措辞仍以导师及学校要求为准。

## 三、REMUS在正文中首次出现的位置与用法

### 1. 首次引入

正式学位论文宜在第一章完成“背景与意义→研究现状及不足→研究目标”的论证后，于**研究目标与主要研究内容**部分首次正式定义REMUS；不要在研究背景开头就直接从系统名称讲起。中文摘要如需使用REMUS，应在摘要中独立给出定义，不能依赖正文的首次引入。

可参考下列段落，正式使用时须根据最新实现情况核实动词和成果状态：

> 针对现有多FPGA原型验证系统内部状态可观测性有限、难以支持确定性重放等问题，本文研究面向大规模SoC的可重放多FPGA硬件仿真技术，并设计实现多FPGA硬件仿真系统REMUS（Replay EMUlation System）。该系统承接课题组已有单FPGA仿真系统REMU的技术基础，围绕自动化电路划分、周期精确执行与一致暂停、分布式状态管理以及可扩展互连等方面开展研究，为大规模设计的可重放仿真提供方法与实验平台。

### 2. 后续章节用法

- 讨论普遍性技术问题时，以“多FPGA周期一致性控制”“分布式状态提取”“自适应粒度划分”等**问题或方法名称**为主。
- 讨论具体实现时，可以使用“REMUS统一周期控制器”“REMUS系统总体架构”“REMUS状态管理流程”等称谓。
- 系统集成与实验章节可以直接使用“REMUS原型系统”“REMUS功能与性能评估”等标题。
- 建议在首次定义后安排一处**REMUS总体架构**介绍，使各关键技术有共同的系统上下文；具体放在相关技术之后，还是系统设计章节开头，以最终论文结构为准。
- 不要求各章节标题都包含REMUS，也不应将某项通用技术仅仅因为在REMUS中使用就描述成原创贡献。

## 四、技术问题、研究方法与系统工程的边界

学位论文应完整交代REMUS的主要技术方向，但不同方向的论证重点不同：

| 技术方向 | 应重点论证的问题 | 实现与验证内容 |
| --- | --- | --- |
| 周期精确执行与可重放仿真 | 跨FPGA逻辑周期一致性、全局一致暂停、分布式全局状态形成及恢复重放的条件 | LI-TDM与控制机制、Scan Dump、Snapshot/Restore、Replay及正确性验证 |
| 自动化电路划分 | 资源约束与均衡、Cut Size、分区传播深度（PPD）、划分粒度选择和自动化 | 自适应粒度、资源估计、超图划分、RTL分区生成及指标评估 |
| 可扩展互连与运行时 | 异构物理链路、分布式控制与状态传输的可扩展性 | Fabric Topology、数据/控制平面、命令分发、状态汇聚与分发 |
| 系统实现与实验 | 各机制能否在真实多FPGA平台上协同工作及其代价 | 双FPGA及后续扩展平台、DUT运行、调试功能、资源与性能数据 |

需要保持如下区分：

- **问题/约束**：如何同时满足资源平衡、降低Cut Size和PPD、选择适当粒度并实现自动部署。
- **方法/手段**：自适应粒度划分、相应超图与RTL处理流程。
- **机制/性质**：跨节点逻辑周期一致、稳定的全局暂停点、可映射的分布式状态集合。
- **系统/实验**：REMUS具体组件以及功能、性能、资源开销和规模扩展实验。

不要仅因某项功能有大量RTL、驱动或Runtime开发工作，就将其自动列为独立学术创新点。具体贡献必须经过相关工作对比、明确的技术差异和实验证据支撑。

## 五、中期报告与最终学位论文的组织

两类文稿共享研究主线，但承担不同任务：

- **中期报告**：对照开题目标，交代阶段性设计、已完成的功能与实验、存在问题及后续计划。不得把正在计划的Restore/Replay、规模扩展或性能目标写成已验证结果。
- **最终学位论文**：完整论证背景与研究空缺、关键问题、所研究方法、REMUS系统设计实现、功能与性能实验、局限和结论。三个技术方向都应有充分交代，但篇幅不必平均分配。
- **论证顺序**：研究背景与意义 → 现有工作与不足 → 研究目标 → 关键技术问题与方法 → 系统架构与实现 → 实验验证 → 总结与展望。正式章次可根据写作需要调整。
- **核心技术线索**：周期精确执行 → 一致暂停 → 分布式状态提取 → 全局Snapshot → 状态恢复与确定性重放。自动化划分与可扩展互连解释上述能力如何用于更大规模和不同硬件环境。
- 当前中期报告的具体章节安排仍以[中期大纲](../src/midterm/outline.md)为准；该顺序不必被机械复制成最终学位论文的章次。

## 六、学位论文与会议、期刊论文的区别

**学位论文**应完整交代REMUS各项研究内容及其协同关系，包括必要的工程实现、平台搭建、技术决策和端到端实验。

**独立投稿的学术论文**可以聚焦其中一个或部分关键问题，例如分布式一致暂停与确定性重放；其他模块即使投入大量工程工作，也可以作为背景、系统支持或实验环境简要介绍。另一篇论文也可能选择自适应粒度划分作为核心问题。

是否形成独立论文，应取决于该方向的创新性、已有工作差异和实验支撑；不能预设每个工程模块都必然具有独立发表价值。系统论文则可以将REMUS整体作为研究对象，但仍需明确核心贡献，避免将工程功能清单直接作为贡献列表。

## 七、证据、术语及版本管理

- 以现有仓库材料、实验日志和真实结果为依据；区分**已实现、初步验证、计划实现、待评价**，不要提前声称全部功能完成。
- 确定性重放的成立条件（状态完整性、输入与环境行为等）应结合具体方案说明，避免无条件保证任意场景可重放。
- 使用“多FPGA原型验证”“FPGA硬件仿真”“软件RTL仿真”等术语时，根据上下文准确区分，避免概括性否定所有现有原型验证系统的调试能力。
- 中文技术文稿保持术语一致，遵循既有中文与英文缩写相邻不加空格的排版习惯；首次出现缩写时给出准确全称。
- 文献及学术贡献需要有可追溯来源；表格和性能指标不得使用未经验证的数值。
- 本文件为长期指导。命名、题目、实际技术完成程度或导师要求变化时，先更新相应指导，再有选择地同步到新文稿。既有开题材料应作为历史版本保留。
