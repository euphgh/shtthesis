# REMUS学术答辩PPT视觉与制作规范

## 1. 设计定位与来源

本规范适用于REMUS中期与最终学位答辩PPT。延续开题PPT的**白底、醒目标题、细分隔线、图文结合、技术内容优先**的学术风格，同时将旧的红橙主题升级为**深蓝（Deep Navy）+青绿（Academic Teal）+琥珀橙（Amber Orange）**。

开题PPT源文件：`pptx/proposal/proposal-slides.pptx`；中期内容参照[逐页大纲](midterm-presentation-outline.md)。旧开题样式是视觉来源，不是新配色模板；已存在的红橙配色中期草稿也应在最终整合时统一升级。开题材料本身不必改色。

## 2. 色彩规范

| Token | Hex | 用途 |
| --- | --- | --- |
| Primary / Deep Navy | `#183B56` | 主标题、技术区块标题、FPGA及结构图轮廓 |
| Secondary / Academic Teal | `#008C95` | 标题下分隔线、核心机制、正向数据流、重要标签 |
| Accent / Amber Orange | `#DF973E` | 关键路径、挑战、重点箭头、关键指标 |
| Surface / Soft Teal | `#EAF4F3` | 方法/能力/已提出解决方案的浅背景 |
| Surface / Cool Gray | `#F1F5F8` | 普通说明、实验表格、对比面板背景 |
| Text / Dark Ink | `#20354A` | 正文与图注 |
| Muted Text | `#607184` | 页码、辅助信息与次级说明 |
| White | `#FFFFFF` | 幻灯片主背景 |

颜色优先级：深蓝定义结构、青绿强调方法及控制、琥珀橙突出需要注意的技术挑战。绿色/红色不应仅作装饰；“已完成/进行中/计划中”不能只靠颜色区分，必须加文字标签或符号。大型图表遵循统一调色板，并确保灰度打印仍可辨认。

## 3. 字体与字号

- **所有英文标题、正文、图注、表格及技术架构图标签统一使用Arial**；加粗使用Arial Bold。不要混用Aptos、Calibri、Arial Narrow、Noto Sans等其他英文字体。
- 必须出现中文时可使用学校认可的中文字体（建议思源黑体/Noto Sans CJK SC），但英文字母和数字仍以Arial为准。
- 页面主标题建议`28–32 pt`（Arial Bold）；分区标题`19–22 pt`；正文`17–20 pt`；表格/图中标签`14–17 pt`；脚注与页码`10–12 pt`。
- 字号是布局建议而非机械限制。保证投影可读；不得仅通过将大量正文压缩到12pt以下解决拥挤问题。
- 标题采用Title Case或简洁句式，术语拼写统一：`Multi-FPGA`、`Scan Dump`、`Global Pause`、`Snapshot`、`Replay`、`LI-TDM`、`PPD`。

## 4. 页面几何与布局

- 画幅：**16:9宽屏**，建议13.333 × 7.5英寸。页面背景纯白。
- 页边距建议左右0.4–0.55英寸；顶部标题在0.2–0.7英寸区域；正文从标题分隔线以下开始。
- 页面主标题左对齐、深蓝色Arial Bold；标题下方使用一条**青绿色细线**（约1.5–2pt）；底部可保留简洁页码，无需重复绘制装饰性边框。
- 一页只表达一个关键观点，主体优先采用“大图+少量说明”；留白充分，避免长段落和密集多级列表。
- 推荐布局：三段递进、左右对比、四象限挑战图、全宽体系结构、时序/状态流向图，以及简洁的实验对比图表。
- 机制介绍优先“问题→方法→结果”；前后页关键术语和图例应连续复用。

## 5. 技术图与图表语言

- **统一视觉语义**：深蓝色用于FPGA/Host/Runtime等结构组件；青绿用于周期控制、Scan Dump和状态流；琥珀橙用于关键约束、瓶颈或突出路径。
- 数据路径与控制路径通过颜色、箭头形态或虚实线组合区分；不要仅依靠红绿颜色判断含义。
- FPGA芯片、逻辑波形、Global Snapshot数据库等图标使用一套一致的学术简笔画。优先复用`figure/`中的资产。
- 架构图尽量保持逻辑准确：物理时钟与DUT逻辑时钟明确分离；Local Dump和Global Snapshot使用不同图示；Restore/Replay标明操作方向。
- 原型验证与硬件仿真的对比图应表述“典型侧重点/常见局限”，不应无证据地将全部已有系统断言为完全不支持暂停或重放。
- 实验图表必须使用真实数据，带单位、测试条件、必要基线和图例；性能未验证时不使用虚构示例数值代替实测结果。

## 6. 图片资产与PPTX可编辑性

- **插图**：高清PNG（透明背景优先）或SVG可作为独立资产复用，统一放置于仓库`figure/`；原始可编辑文件可保留在该目录的对应子目录。生成图不可覆盖实际实验照片。
- **PPTX**：标题、列表、框、箭头、标签、数据图表和简单流程结构应尽可能由可编辑的PowerPoint元素组成；复杂插图可以嵌入为独立图片。
- 禁止用单张整页设计图替代可编辑的幻灯片。图片应保持比例，避免拉伸、模糊、深色锯齿或残留背景。
- 系统名称统一使用REMUS。开题阶段SMART和旧文件名可保留作历史版本；不因更名擅自重写历史PPT。

## 7. 内容密度与图表模板

| 页面类型 | 建议结构 | 文字量 |
| --- | --- | --- |
| 背景演进 | 三层递进+每层最多3个短语 | 以图为主 |
| 能力对比 | 两栏或三栏对比+一致的图标 | 每栏3–5条 |
| 关键挑战 | 2×2卡片，每卡1个标题和1句解释 | 简短 |
| 系统工作流 | 一张主架构图+辅助图例 | 只标关键节点 |
| 技术机制 | 一张大时序图/状态图+2–3条结论 | 避免逐条解释全部RTL |
| 实验评估 | 2–3组有证据的指标+简短结论 | 不以文字替代数据 |

## 8. 质量检查与交付

1. 检查全部英文文本为Arial（包括图表轴、可编辑标签和主题默认字体）；视觉生成图片中如含文字，也应尽量与Arial一致。
2. 确认16:9、颜色Token、页边距、标题层级、页码以及图标风格一致。
3. 渲染所有页面检查文字裁切、对象重叠、透明边界、图片清晰度、箭头方向及字体替换。
4. 检查每页核心结论能否在几秒内看清；过密内容优先拆页或删减，而不是缩小到不可读字号。
5. 对照中期大纲和实验资料核实DUT名称、状态、技术机制及数据；尚未完成的工作明确标注规划状态。
6. 保留原始PPTX、复用的图片资产；必要时同步输出渲染预览供逐页审阅。只交付视觉图而无可编辑PPTX不算完成PPT制作任务。

## 9. 与开题PPT的继承关系

| 保留 | 升级 |
| --- | --- |
| 白底、标题分隔线、简洁学术布局 | 红色标题改为Deep Navy |
| 左文右图、结构框图、示意图 | 橙色线改为Academic Teal |
| 突出关键技术和直观流程 | 琥珀橙仅用于重点提示 |
| 明确的标题与正文层级 | 英文统一Arial；浅色技术卡片与统一图标 |
| 图表解释技术而非装饰 | 结果和状态可追溯、PPT元素可编辑 |

该规范适用于**新制或改版的中期/最终答辩PPT**，不要求追溯性修改已归档的开题演示文稿。
