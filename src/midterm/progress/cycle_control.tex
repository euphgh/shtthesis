\section{多FPGA周期精确执行与一致暂停}
\label{sec:midterm-cycle-control}

电路划分使DUT的逻辑与状态分布在多个FPGA上，也将部分片内组合连接转化为跨片通信。通信过程引入的传输延迟和节点间执行进度差异，需要与原始DUT的逻辑时序相协调。为此，REMUS采用DUOHUAFEN提出的LI-TDM机制，并针对每周期传播流程和通信调试需求进行改造，从而减少了通信开销。在此基础上，通过接收屏障与共同目标周期协调各分区暂停，为后续分布式状态提取建立一致的逻辑时间边界。

\subsection{基于LI-TDM的跨FPGA周期精确执行及改进}
\label{sec:midterm-li-tdm}

在同步RTL设计中，寄存器之间的组合逻辑在相邻时钟边沿之间完成计算，时序状态在有效时钟边沿更新。设计划分到多个FPGA后，一条寄存器之间的组合路径可能多次跨越分区边界，其输入需要经过数据打包、链路传输和接收重组才能到达后续逻辑。如果各分区仅按照本地物理时钟独立更新状态，就可能使用尚未完成传播的输入，改变原始设计的执行结果。因此，跨FPGA周期精确执行需要在数据传播与DUT状态更新之间建立明确的约束。

DUOHUAFEN提出的LI-TDM机制结合了延迟不敏感（Latency-Insensitive，LI）握手与时分复用（Time-Division Multiplexing，TDM），通过分阶段交换边界数据实现跨FPGA的周期精确执行\cite{zhu_duohuafen_2024}。其中，握手用于协调传输过程中的等待，时分复用将较宽的逻辑边界信号分拍映射到有限位宽的通信通道。FPGA物理时钟持续驱动通信与控制逻辑，DUT逻辑时钟则在所需传播完成后推进。一个DUT逻辑周期因而可以占用多个物理时钟周期，通信延迟会改变其实际执行耗时，但不应改变该周期的状态更新语义。REMUS以这一机制为基础，重点改进传播首尾阶段的收发安排，并增加面向调试的数据一致性检查。

原有LI-TDM在逻辑时钟更新后，按照“等待接收边界数据、计算组合逻辑、发送计算结果”的顺序逐阶段传播。传播阶段数需要覆盖划分后组合路径上的跨分区依赖。例如，一条路径从分区A中的寄存器出发，经过分区B中的组合逻辑后返回分区A中的目标寄存器，即使只涉及两个分区，也需要完成往返传播后才能更新目标状态。分区传播深度（Partition Propagation Depth，PPD）用于确定所需的执行阶段数，其分析方法将在自动化电路划分部分展开。这里的传播阶段描述同一逻辑周期内的数据传播进度，与通信路由经过的物理节点数不同。

\paragraph{首尾传播阶段的收发优化}

分析逻辑周期边界的数据依赖可以发现，首阶段与末阶段并不需要执行完整的收发循环。逻辑时钟更新后，各分区已经获得新的本地寄存器值，可以计算由这些值决定的组合结果，并将初始边界数据发送出去，无需先等待一次新的跨片接收。对于仍依赖远端输入的组合逻辑，其结果会随着后续阶段的数据到达而逐步形成，因此首阶段发送并不意味着所有组合输出已经稳定。首阶段也仍需满足本地输入和模型交互条件，所省去的是跨片接收等待。

中间阶段继续执行接收、组合计算与发送，使新周期的数据沿跨分区组合路径传播。在最后一个传播阶段，所需数据经接收和本地组合计算后，已经到达目标时序逻辑；此时无需再为下一传播阶段发送计算结果，可以完成当前周期并推进DUT逻辑时钟。由此，REMUS将首阶段调整为“计算后发送”，将末阶段调整为“接收后计算并更新时钟”，如表\ref{tab:midterm-li-tdm-stages}所示。

这一调整在每个逻辑周期内省去一次接收和一次发送，合计减少一轮跨片数据交换。改进利用的是时序边界两侧不同的数据依赖，不改变电路划分结果，也不减少组合依赖必须经过的传播范围。其效果是降低每周期的通信与等待开销，实际运行时间的改善还取决于PPD、边界数据量、链路延迟以及本地模型响应时间，具体性能需要通过系统实验评价。

\paragraph{基于周期与传播阶段标识的通信序列一致性检查}

多分区通信涉及握手、缓存和传播调度等多个环节。实现中的缺陷可能导致数据包缺失或重复，物理信道的顺序异常也可能使数据不按预期到达。如果缺少传输过程中的检查，这些问题可能在传播若干逻辑周期后才表现为程序输出错误，难以回溯到最初出错的位置。

为提高通信过程的可诊断性，REMUS在边界数据中增加逻辑周期与传播阶段标识，使接收端能够判断数据属于哪个逻辑周期、哪个传播阶段。接收时，将数据携带的标识与本地当前周期及允许接收的阶段关系进行比较；只有满足相应关系的数据才作为有效输入参与后续执行。由于发送与接收位于传播过程的不同位置，这一检查依据的是协议规定的阶段对应关系，而非要求两端的阶段编号简单相等。

当缺失、重复或乱序使数据偏离预期执行上下文时，仿真中的一致性检查能够在接收边界报告异常，并给出相关周期与阶段信息。这样可以将部分延后显现的DUT功能错误转化为更接近出错位置的通信协议错误，为排查控制逻辑缺陷和检查信道顺序提供依据。该机制用于错误检测与定位，不承担自动重传或乱序重排，也不能单独覆盖所有异常：同周期、同阶段的重复数据可能仍具有合法标识，而缺失数据后若没有后续数据到达，则还需要结合超时或收发计数检查。

通过上述改造，REMUS保留了LI-TDM按传播完成条件推进DUT的执行语义，同时减少首尾阶段的冗余通信，并增加对传输顺序的检查。运行过程中，不同分区的逻辑周期推进事件可以发生在不同物理时刻；周期精确性要求的是相应逻辑周期的计算与状态更新正确，而不是任意物理时刻所有分区计数器都相等。这一区别也是进一步设计一致暂停机制的出发点。

\subsection{多FPGA一致暂停机制}
\label{sec:midterm-global-pause}

在多FPGA系统中，主机向各分区下发的控制请求通常无法同时到达，各分区收到请求时也可能处于不同的传播阶段。即使每个分区都能在本地逻辑周期边界停止，最终停止的周期仍可能不同。因此，全局一致暂停需要协调各分区的执行进度，使其完成相应周期的计算与通信后，在同一目标逻辑周期停止DUT状态更新。暂停期间，通信和主机控制逻辑仍由物理时钟驱动，以完成必要的协调与状态访问。

REMUS的一致暂停机制与扫描链控制器交互，利用其周期计数、运行状态和定步执行能力组织暂停过程。逻辑周期计数寄存器记录分区已完成的执行进度，运行与暂停状态位用于反映当前模式和暂停请求的处理情况，剩余步数寄存器用于指定还需执行的逻辑周期数。此外，同步屏障请求与确认状态为主机采样稳定进度、配置共同暂停目标提供协调接口。运行与扫描控制的统一以及具体状态提取过程将在下一节讨论。

\paragraph{接收屏障与执行进度采样}

主机首先向各分区设置同步屏障请求。分区收到请求后，完成进入下一接收边界所需的前序动作，并在接收边界保持传播进度，向主机返回屏障确认。确认不要求本阶段待接收的数据已经有效，使分区能够在尚未完成当前接收的情况下保持进度，等待主机安排后续执行。

主机收齐各分区的屏障确认后，读取其逻辑周期计数。由于分区在屏障保持期间不再推进传播阶段，依次读取计数不会受到持续执行造成的变化影响。各分区此时的计数仍可能不同，通信缓存中也可能保留数据。因此，接收屏障仅用于建立稳定的协调位置，不是最终的全局暂停点，屏障确认也不能等同于通信已经排空。

\paragraph{共同目标周期与分区步进协调}

设系统共有$N$个分区，分区$i$在接收屏障处的逻辑周期计数为$c_i$。主机选择所有已采样周期之后的一个周期作为共同暂停目标：
\begin{equation}
    T = \max_{0 \leq i < N} c_i + 1.
    \label{eq:midterm-pause-target}
\end{equation}
随后，为每个分区设置剩余执行步数
\begin{equation}
    s_i = T - c_i, \qquad 0 \leq i < N.
    \label{eq:midterm-pause-steps}
\end{equation}
这一选择使各分区的剩余步数均为正，能够继续完成屏障处尚未结束的周期执行，同时避免要求领先分区回退状态。

步数配置在屏障保持期间完成，随后主机按照逻辑进度从落后到领先的顺序解除各分区的屏障。解除后，各分区仍通过原有跨分区握手机制完成数据传播，每完成一个DUT逻辑周期便递减剩余步数。例如，若两个分区在屏障处的计数分别为42和41，则共同目标为43，剩余步数分别为1和2，并优先解除计数为41的分区。这个例子说明，各分区到达共同暂停点所需的执行步数可以不同，主机无须同时送达所有控制写请求。

当剩余的最后一步执行完成时，分区停止正常运行。主机逐分区检查运行及暂停处理状态，并重新读取逻辑周期计数，只有全部分区均停止且计数等于式\eqref{eq:midterm-pause-target}确定的目标$T$，才报告同步暂停完成。进入屏障和等待最终暂停分别设置等待上限；对目标周期溢出、步数超出寄存器范围或最终计数不一致等情况，显式报告错误，避免将未完成的协调误认为有效暂停。

\paragraph{全局暂停点的状态语义}

共同目标周期给出了各分区状态所属的统一逻辑时刻，但周期计数相等本身不足以说明内部状态正确。有效的暂停点还要求到达目标周期所需的计算和跨分区数据传播已经完成，DUT状态不再因正常执行而更新。单个发送接口已接受数据，或者某个分区已经确认屏障，都不能替代这一条件。暂停后的状态需要与未划分DUT在相同逻辑周期的状态对应，才能作为后续分布式状态提取的基础。

因此，在功能验证中，将暂停完成的周期检查与参考DUT的内部状态对照结合起来，分别检验分区是否停在同一周期，以及是否到达该周期应有的状态。这里的一致暂停解决全局状态的时间边界问题；状态覆盖、映射、恢复及重放所需的其他条件，由后续分布式状态管理机制进一步处理。

\subsection{Cosim功能验证}
\label{sec:midterm-cycle-cosim}

本阶段以PicoRV32和香山昆明湖（KMH）为DUT，在Cosim环境中对周期精确执行与一致暂停机制进行了功能验证。对每个DUT分别建立划分前的单体仿真与划分后的多分区仿真，运行相同的软件程序。单体仿真作为参考，多分区仿真包含跨分区数据交换与主机运行控制，比较以DUT逻辑周期为基准，而不以两种环境的物理执行耗时为基准。

\paragraph{周期精确执行验证}

为验证划分后设计的执行行为，在两种仿真中运行相同的软件程序，并使DUT执行相同数量的逻辑时钟周期，再比较对应执行进度下的程序输出。测试结果表明，PicoRV32和KMH在划分前后的程序输出相同。这为所测试程序和执行区间内，跨分区传播及首尾阶段收发优化保持相应执行结果提供了实验支持。

上述对照检查了设计在通信等待与多阶段传播条件下的程序输出，结论限于实际测试的程序和执行区间，不能据此推定任意程序、任意周期上的全部内部状态均已得到验证。

\paragraph{一致暂停验证}

为验证一致暂停功能，在多分区Cosim运行过程中由主机发出暂停请求，等待协调过程结束后，读取各分区的逻辑周期计数，检查是否到达同一个目标周期。随后，将未划分DUT的单体仿真运行到相同逻辑周期，依据原始DUT状态与分区状态的对应关系，比较暂停时的内部状态。

PicoRV32和KMH的测试结果均表明，各分区能够停在同一逻辑周期，暂停时的内部状态与参考单体仿真在对应周期的状态相同。周期计数对照验证了暂停位置的一致性，内部状态对照进一步检查了暂停点的功能正确性，从而为后续在该时间边界上提取分布式状态提供依据。状态的提取和映射方法将在下一节说明。
