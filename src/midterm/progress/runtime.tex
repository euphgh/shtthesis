\section{可扩展的多FPGA运行控制架构}
\label{sec:midterm-fabric}

前文介绍了一致暂停和分布式状态管理的方法。执行这些操作时，主机需要访问各FPGA上的控制寄存器和内存。例如，一致暂停需要读取各分区的周期计数并配置剩余步数，程序加载则需要向指定分区的内存写入数据。因此，除了DUT分区之间的通信，多FPGA系统还需要建立从主机到各节点资源的访问通路。本节先介绍基于PCIe直连的基础架构，再说明如何通过Fabric提供统一访问入口，减少系统对主机直连接口数量的依赖，从而实现可扩展的多FPGA运行控制。

\subsection{基于PCIe直连的多FPGA运行控制}
\label{sec:midterm-direct-host}

一种直接的实现方式是由主机（Host）通过PCIe分别连接所有FPGA。每个FPGA向主机提供本地控制寄存器和内存访问接口，主机独立访问各节点，控制请求无须经其他FPGA转发。硬件侧可以沿用板卡已有的PCIe接口和本地总线结构，因而容易从单FPGA运行控制扩展得到。与此同时，各FPGA之间的跨片链路仅仅用于交换DUT边界数据，主机访问与DUT跨分区通信的信道相互独立。

在软件侧，Driver建立逻辑分区、目标FPGA与PCIe设备文件的对应关系。初始化时打开各节点的设备文件，并将得到的文件描述符保存在相应访问对象中。访问某个FPGA时，Driver选择该节点的访问对象，再对其局部地址执行读写。寄存器与内存可以使用不同的设备文件：寄存器通常通过PCIe基地址寄存器（Base Address Register，BAR）窗口映射访问，内存数据则可以通过直接内存访问（Direct Memory Access，DMA）设备传输。因此，一个FPGA不必只对应一个文件描述符，但这些设备都归属于同一节点。

例如，读取FPGA B的逻辑周期计数时，Driver选择B的寄存器访问对象，并读取周期计数寄存器的局部偏移。向B加载程序时，则选择B的内存访问对象，将程序数据写入指定区域。这种组织方式将节点选择和资源读写直接对应起来，软件只需维护清楚的设备映射，便可组合寄存器操作实现运行、定步执行及暂停协调。第\ref{sec:midterm-global-pause}节的一致暂停协议也可以通过这些独立访问通路执行。

这一架构的限制在于，每个FPGA都需要占用主机侧的PCIe连接资源。随着节点数量增加，主机需要提供更多插槽、PCIe通道或相应扩展设施，可直接连接的板卡数量因而受到平台条件限制。为进一步扩展系统，需要使未与主机直接连接的FPGA也能接收资源访问请求，并尽量保留软件按节点读写寄存器和内存的方式。

\subsection{基于Fabric的统一访问架构}
\label{sec:midterm-fabric-architecture}

针对上述限制，REMUS采用Fabric连接各FPGA，并选择其中一个节点作为主机接入点。该节点称为参考节点Ref，通过PCIe与主机连接，其余普通节点通过板间链路接入Fabric。Ref与普通节点均承载本地DUT分区、控制寄存器和内存，Ref额外承担主机请求的接入与响应返回。主机通过Ref即可访问各节点的资源，普通节点不再要求分别建立独立的主机PCIe连接。两种架构的连接方式如图\ref{fig:midterm-fabric-architecture-comparison}所示。

Fabric为主机提供面向目标节点的统一资源访问接口。一次访问由目标节点、该节点内的局部地址以及读写操作共同确定。目标为Ref时，请求在Ref内部执行。目标为普通节点时，请求经板间链路送往对应FPGA。两种情况下，主机均以相同的方式指定目标资源，并获取访问结果。寄存器接口用于运行控制和状态查询，内存接口用于程序及模型数据等内容的传输。

Driver在上层仍为各分区提供独立的寄存器和内存对象，但这些对象共享Ref的接入通路。底层根据目标节点与局部地址组织请求，上层控制流程不必根据节点是否与主机直连而改变访问步骤。例如，一致暂停仍由Driver读取各分区进度、计算共同目标并配置步数，Fabric负责将相应寄存器访问送到目标节点并返回结果。

通过这一结构，系统增加FPGA时可以利用板间互连扩展访问范围，减少对主机直连接口数量的依赖。不过，统一入口也使主机访问流量共享Ref的接入带宽，实际可扩展规模仍受板间连接、传输带宽和具体实现条件限制。

\subsection{Fabric组件及统一访问过程}
\label{sec:midterm-fabric-access}

Fabric中的资源访问由访问发起器（AccessInitiator）、路由器（FabricRouter）和访问代理（AccessAgent）协作完成。各节点的Router通过板间链路连接，接口适配逻辑负责将统一通信接口接到具体板级链路。表\ref{tab:midterm-fabric-components}概括了这些组件在主机访问过程中的职责。

        AccessAgent     & 在目标节点通过本地总线访问寄存器或内存，并形成响应        \\

以主机读取普通节点FPGA B的周期计数为例，图\ref{fig:midterm-fabric-remote-access}展示了请求与响应经过各组件的路径。首先，Driver指定B的节点身份和周期计数寄存器的局部地址，通过Ref的PCIe接口提交读取请求。Ref中的Initiator将请求转换为Fabric报文，其中包含目标节点和本次操作的信息。随后，Ref的Router将报文发送到板间链路，B的Router接收后将其投递给本地Agent。

Agent将请求转换为本地总线访问，读取DUT控制器中的周期计数寄存器。待本地访问完成后，Agent生成包含读取值及执行状态的响应，经Router和板间链路返回Ref。Ref的Initiator匹配该响应与原请求，并向主机返回结果。这样，远端寄存器的实际读操作发生在B上，而主机只需通过Ref提交请求并等待完成。

访问Ref自身的资源时，Initiator发出的普通资源请求由本地Router投递给Agent，无须经过板间链路。内存读写采用相同的发起、目标投递、执行与响应返回关系，只是Agent连接的是目标节点的本地内存接口。普通节点也可以配置面向节点侧请求的发起器；对于本节关注的主机访问，关键在于Ref能够发起请求，而目标节点能够通过Agent执行访问。

这些组件将节点选择、跨片传送与本地资源操作连接起来，使主机能够以统一方式访问各FPGA。运行控制所需的寄存器读写和状态管理所需的内存访问由此获得共同的访问基础。

\subsection{阶段性实现与验证}
\label{sec:midterm-fabric-validation}

\paragraph{统一访问通路的实现}

目前已实现访问发起器、路由器和访问代理，并将相关组件接入Ref与普通节点的Role结构。Driver的Fabric后端提供面向各分区的寄存器和内存对象，共享Ref访问入口。围绕这条通路，已建立双节点Role联合仿真环境：每个节点由独立仿真进程运行，主机请求从Ref侧总线接口进入，经过Fabric组件到达目标资源，再将响应返回主机。仿真环境在Role边界模拟主机、内存和板间链路服务，保留节点内部的实际RTL访问路径。

\paragraph{寄存器与内存访问验证}

统一访问的验证有两个关键的测试点：请求是否到达指定节点，以及返回的数据是否来自实际执行的资源访问。对于寄存器，分别读取Ref与普通节点的身份、状态寄存器，检查返回值是否与目标节点对应。对于可读写寄存器，写入测试值后回读，并与预期值比较。对于内存，在两个节点的相同局部地址写入不同数据，再分别回读，检查内容是否一致以及节点之间是否出现错误覆盖。采用不同测试数据可以避免将目标节点选择错误误判为读写成功。

在数据比较之外，还需结合请求与响应记录检查访问路径。远端请求应经历Ref发起、跨节点转发、目标侧总线访问和响应返回，不能仅依据主机命令正常退出判定统一访问正确。对于无效目标或越界地址，还应检查失败是否以错误结果返回，避免软件将未完成的访问当作成功。

\paragraph{阶段性结果与验证边界}

已有开发记录包含访问发起器、内存访问及Driver相关测试的通过结果，双节点Role工程也已完成结构检查和联合仿真环境搭建。这些记录分别为组件功能、软件访问适配和工程连接提供了阶段性依据。当前可追溯记录尚未给出完整双节点Role寄存器、内存访问的联合验收结果，因此本节暂不将上述局部测试扩写为统一访问通路已经全部通过。后续将按前述方法补充目标节点、测试数据、回读比较和访问路径记录，形成联合验证结果。
