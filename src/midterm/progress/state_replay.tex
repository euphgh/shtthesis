\section{分布式状态提取、恢复与重放}
\label{sec:midterm-state-replay}

第\ref{sec:midterm-global-pause}节介绍的一致暂停机制，使多个FPGA能够停止在同一个DUT逻辑周期。但各分区的寄存器和存储器状态仍保存在不同的硬件节点中。要将这些状态用于检查、恢复和重放，还需要分别提取局部数据，并确定它们与原始DUT状态之间的对应关系。本节在REMU已有状态管理机制的基础上，介绍REMUS的分布式状态组织、提取及恢复方法，并给出阶段性验证结果。

\subsection{分布式状态模型与全局检查点设计}
\label{sec:midterm-global-snapshot}

\paragraph{REMU状态管理基础与多FPGA问题}

单FPGA仿真系统REMU已通过扫描链覆盖DUT的全部寄存器和SRAM，支持内部状态的导出与写回\cite{chen_remu_2023}。除扫描数据（Scan Chain）外，REMU还保存DUT使用的内存数据（Memory），并按照DUT逻辑周期记录外部输入的变化（Input）。其中，扫描数据与内存数据用于恢复检查点时刻的执行状态，输入记录用于恢复外部输入并重现后续变化。这些机制构成REMUS状态管理的基础。

当DUT划分到多个FPGA后，寄存器和SRAM分散在各分区中，单个FPGA的扫描数据不再包含完整DUT的时序状态。REMUS为每个分区保留独立的扫描结构，使其能够保存本地状态；Memory与Input目前仍沿用REMU原有机制，集中由一块FPGA管理。因此，多FPGA扩展的重点不是重新设计扫描链，而是解决两个问题：一是各分区提取的状态必须对应同一个DUT逻辑周期；二是各分区的局部扫描数据必须能够映射到未划分DUT中的逻辑状态对象。前者由1.2节的一致暂停机制解决，后者需要在编译阶段建立状态映射。

\paragraph{全局检查点的数据组织}

REMUS将同一逻辑周期的分区扫描数据与Memory等信息组织为全局检查点（Global Snapshot）。各FPGA的扫描数据分别保存为独立文件，通过共同周期和分区标识关联，而不必拼接为一条跨FPGA扫描数据。表\ref{tab:midterm-checkpoint-content}列出了检查点及其配套信息的主要组成。

\paragraph{局部扫描布局与全局状态映射}

局部扫描文件只记录按扫描顺序排列的数据。划分之后，不同分区可能具有相同的局部扫描偏移，仅凭偏移无法确定一段数据对应原始设计中的哪个寄存器。为此，REMUS在编译阶段记录各分区的扫描布局，建立“分区标识—局部扫描位置—未划分DUT逻辑状态”的对应关系。映射信息包括状态所属分区、扫描位置、位宽以及必要的层次和存储器描述。

这一映射主要用于软件RTL状态恢复：软件按分区读取扫描数据，将局部比特对应到原始DUT的逻辑状态，再加载到配套的重放RTL对象中。对于FPGA恢复，如果使用相同的分区设计及扫描布局，则可以直接将各分区的扫描数据写回对应FPGA，不必先还原为原始DUT的层次结构。无论采用哪种方式，检查点、状态映射和相关编译产物都需要保持匹配。

\subsection{分布式状态提取与扫描控制协同}
\label{sec:midterm-scan-control}

建立全局检查点的组织方式后，还需要从运行中的多FPGA系统中获取各分区状态。REMUS复用REMU已有的局部扫描机制，但扫描启动必须与跨分区逻辑周期控制相协调，否则不同FPGA可能导出不同逻辑时刻的状态。

\paragraph{划分控制与运行控制的协同}

REMU已有运行、暂停、定步执行和扫描模式控制。引入LI-TDM跨分区传播后，本地模型完成交互并不意味着当前DUT逻辑周期已经结束。如果此时更新寄存器或周期计数，就可能出现执行进度与实际DUT状态不一致的问题。为此，REMUS将划分控制机产生的逻辑周期完成信号接入原有运行控制，使DUT时序状态更新、逻辑周期计数和剩余执行步数使用同一个完成条件。

两部分控制逻辑还交换运行使能、同步屏障请求及确认等信息，用于协调跨分区暂停。划分控制机负责传播阶段和周期完成条件，运行与模式控制负责执行进度和模式切换；具体的局部扫描移位仍由REMU已有的扫描控制逻辑执行。

\paragraph{一致暂停后进入扫描模式}

主机首先按照第\ref{sec:midterm-global-pause}节的方法完成全局一致暂停。需要注意，接收屏障确认只表示各分区停在可稳定采样进度的位置，并不代表已经完成一致暂停。只有全部分区到达共同的目标逻辑周期，且相关模型满足扫描访问条件后，主机才协调切换到扫描模式。

进入扫描模式后，各分区分别按REMU已有的扫描协议导出本地寄存器和SRAM状态。扫描操作虽然消耗FPGA物理时钟周期，但不增加DUT逻辑周期计数，因此各分区能够在同一逻辑时刻停止执行后分别完成状态访问。

\paragraph{局部状态导出与主机汇聚}

各FPGA先将Scan Dump数据写入本地DDR，随后由Host分别读取并保存为对应分区的扫描文件。各分区可以先后完成扫描和数据收集，无须在同一物理时刻返回状态。只要保持有效的一致暂停状态，并遵循既有扫描协议，收集到的数据就能够对应同一个DUT逻辑周期。

最后，Host结合分区标识、周期信息和状态映射，将这些文件组织为Global Snapshot。至此，分布式状态提取形成了从一致暂停、局部扫描到全局检查点的完整流程。Host如何控制各分区以及如何访问不同FPGA上的DDR，将在1.5节介绍。

\subsection{基于全局检查点的状态恢复与确定性重放}
\label{sec:midterm-state-restore-replay}

全局检查点不仅用于保存和检查状态，也需要能够作为后续执行的起点。确定性重放（Replay）的第一步是状态恢复（Restore）：将DUT、内存和输入恢复到指定检查点，再按照记录重新执行之后的输入变化。REMUS沿用REMU的恢复与重放功能，新增工作主要是让分区检查点能够被正确加载。

\paragraph{从全局检查点恢复状态}

在FPGA上执行Restore时，Host依据分区归属将扫描数据送回对应FPGA，复用REMU的Scanin恢复各分区的寄存器和SRAM，并恢复Memory数据。待全部分区完成恢复后，系统才能从该检查点继续执行。

在软件RTL仿真中，Restore不通过硬件扫描链完成，而是利用全局状态映射解码各分区扫描数据，再将状态加载到对应的RTL仿真对象，同时恢复Memory。两条路径的加载方式不同，但使用的是同一个全局检查点。对于Input，硬件Driver和软件重放程序均根据完整输入记录确定检查点时刻的初始值，而不依赖单独保存的输入快照。

\paragraph{恢复后的确定性重放}

状态恢复完成后，Replay还需要按照DUT逻辑周期重现检查点之后的Input变化。硬件沿用REMU已有的定步执行与输入寄存器控制机制，软件RTL仿真则使用已有的VPI定时回调机制，在对应仿真时间更新输入。软件重放期间还可以导出内部波形，用于分析硬件运行中发现的问题。

上述两种重放方式都建立在正确恢复Global Snapshot的基础上。REMUS的扩展重点是将多分区状态接入原有流程，而非重新设计输入调度或波形导出机制。是否实现了预期的重放效果，还需结合恢复后执行结果及相应状态对照加以验证。

\subsection{功能验证与阶段性结果}
\label{sec:midterm-state-validation}

本节主要验证两项能力：分区扫描数据能否正确还原为未划分DUT的逻辑状态，以及形成的Global Snapshot能否供恢复与重放使用。

\paragraph{分布式状态提取与映射验证}

状态提取实验比较PicoRV32和KMH的多分区Cosim与单体RTL仿真。多分区设计在一致暂停后执行Scan Dump，将扫描数据保存并按分区映射解码；单体RTL仿真运行到相同的DUT逻辑周期，作为状态对照。

已有测试中，两种设计在实际比较的内部状态范围内结果相同，说明在已测试条件下，分区扫描、数据收集和状态映射能够得到与单体参考一致的状态。这一结果不等于全部内部状态或所有执行周期均已完成逐位对照。

\paragraph{非零周期检查点的恢复与重放验证}

为验证检查点能否用于后续执行，已有实验从非零逻辑周期保存的检查点出发，分别进行软件RTL Replay及FPGA上的Replay、Restore。已有测试的后续运行结果符合预期，继续运行后再次保存的检查点数据也符合预期。表\ref{tab:midterm-state-replay-tests}汇总了现阶段的定性结果。

该实验以检查点周期$T_0$和后续目标周期$T_1$描述比较过程。参考路径从相同初始条件运行至$T_1$；恢复路径将$T_0$的分区扫描状态、Memory及相应Input加载完成后，重现$(T_0,T_1]$内的输入变化，再比较$T_1$处的程序输出与选定状态。软件RTL路径则在相同恢复点加载映射后的状态，记录后续内部波形。这样，验证对象不仅是检查点文件能否读写，还包括恢复点是否足以重现后续执行。只有保持状态、输入记录及编译产物匹配，才能据此讨论确定性重放。

\paragraph{后续实验与评价}

现有板级日志已记录PicoRV32和KMH的检查点加载、保存及扫描阶段耗时，第\ref{sec:midterm-prototype-results}节将结合有效数据量分析其开销。后续重点是补充恢复重放案例的对照材料、扩大状态比较范围，并在更多分区及工作负载下评价适用性，而不是以加载计时正常结束替代恢复正确性判断。
