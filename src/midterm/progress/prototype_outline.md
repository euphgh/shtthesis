# 1.6 双FPGA仿真加速原型系统与阶段性实验：详细大纲

本节将前文的电路划分、跨片执行、运行控制和分布式状态管理集成到双FPGA平台，以不同规模的RISC-V处理器为对象，验证裸机程序与操作系统运行、全局检查点及恢复重放，并评价系统性能和资源开销。叙事顺序为：实验平台→DUT部署与运行→一致暂停及恢复重放→性能与资源开销。

本文件为独立写作大纲，对应`prototype.tex`，不替代已取得的实验记录。平台与功能完成状态依据作者在本次大纲讨论中的确认；相关实测记录尚未纳入仓库，待补参数和定量结果统一使用`x`占位。数据整理时应补充版本、配置、比较范围及原始记录位置，不将占位内容当作实测结果。

## 1.6.1 实验平台与系统配置

### （1）双FPGA硬件平台

- 实验使用两块课题组开发的NM37板卡，核心器件为VU37P FPGA，每块板卡提供三个光口。
- Host通过PCIe分别访问两块FPGA，板间通过QSFP连接，采用Aurora承载DUT跨分区数据。
- 本节板级实验采用PCIe直连控制架构，不将其作为1.5中Fabric统一访问架构的板级验证结果。

### （2）时钟与系统集成

- Shell运行在250 MHz，Role中的DUT执行与扫描链等电路运行在50 MHz，相关接口通过AXI组件完成跨时钟域处理。物理时钟由板卡上的时钟生成器产生。
- 区分上述物理时钟与DUT有效逻辑运行频率：一个DUT逻辑周期需要经历计算、跨片传输和控制等待，不能将50 MHz直接作为仿真速度。
- 简述两个Part与各自Role、Shell的集成关系，以及DDR承载内存模型和扫描数据的方式，不展开具体构建命令。
- 补充Aurora每lane速率`x`、lane数量`x`及实际启用的QSFP端口数`x`。

## 1.6.4 系统性能与资源开销

### （1）有效逻辑运行频率

- 分别统计四个DUT在指定负载或执行区间内的逻辑周期数与实际耗时，报告有效逻辑运行频率`x` MHz。
- 区分持续执行速度与包含加载、暂停和检查点操作的端到端耗时；人工命令行输入等待单独处理。
- 结合最大路径切割数、边界数据量及通信等待，分析不同DUT运行速度的差异。
- 将已有的0.36 MHz与0.5 MHz作为传播流程优化的对照结果，补充对应DUT、划分及测量条件，解释减少冗余交换对实际运行速度的影响，不推广为所有DUT的固定收益。
- 当前Driver的`elapsed_s`和`rate_mhz`提供软件观测的耗时与运行速率，不是FPGA物理时钟频率；原始日志需保留计时区间。

### （2）一致暂停与检查点开销

- 记录一致暂停耗时`x`、全局检查点大小`x`、保存耗时`x`及恢复耗时`x`。
- 分别说明分区扫描数据和内存数据的规模，避免将内存镜像大小等同于DUT扫描状态大小。
- 有细分数据时，分析扫描操作、Host传输及文件保存各自的耗时；否则报告明确起止边界的完整操作时间。
- 结合不同DUT的数据规模，分析状态管理开销的变化。
- 当前Driver已有保存/加载状态、内存及总过程的计时入口；`save`耗时不直接等于“暂停并保存总耗时”。

### （3）FPGA资源与时序结果

- 分别报告两个Part的LUT、FF、BRAM、URAM和DSP占用，未使用的资源按实际结果填写。
- 说明资源统计包含DUT、扫描与控制逻辑、Role或Shell中的哪些部分。

- 结合层次化资源报告分析主要开销；只有具备匹配的基线设计时，才计算新增机制的资源开销比例。

小节最后归纳：系统已经在双FPGA平台上完成四类DUT的运行和恢复重放验证；定量结果说明其性能与代价，但双FPGA实验不直接证明更多节点或Fabric架构下具有相同表现。总体研究总结留到1.7，不在此重复展开。
