# 1.5 可扩展的多FPGA运行控制架构：详细大纲

本节按照“PCIe直连基础架构→主机接口数量限制→Fabric统一访问架构”的顺序展开，解释各组件如何配合，使Host访问所有FPGA的寄存器和内存。

## 1.5.1 基于PCIe直连的多FPGA运行控制

### 基础连接结构

- Host通过PCIe分别连接各FPGA，每个FPGA提供本地控制寄存器和内存访问接口。
- 硬件侧沿用各板卡已有的PCIe访问能力，Host可以独立访问每个节点，控制访问无需经过其他FPGA转发。
- FPGA之间仍保留DUT运行所需的跨片数据连接；这里的PCIe直连描述Host管理节点的方式。

### 软件中的节点与设备映射

- Driver建立逻辑分区、目标FPGA与PCIe设备文件之间的对应关系，打开对应设备并保存文件描述符。
- 访问某个FPGA时，选择其寄存器或内存访问文件描述符，再执行局部地址读写。一个FPGA可能对应不同用途的设备文件。
- 例如，读取FPGA B的周期计数时选择B的控制设备，向B加载程序时选择B的内存访问设备。
- 软件只需维护明确的节点与设备映射，上层运行控制由这些读写操作组成，便于实现和调试。周期一致暂停机制引用1.2，不重复展开。

### 主机接口数量带来的限制

- 每增加一个FPGA，Host需要增加相应的PCIe连接与设备管理资源。
- 主机PCIe插槽、通道及可连接板卡数量有限，逐节点直连限制了系统规模扩展。
- 需要使未与Host直连的FPGA也能被访问，减少Host直连需求，并保留按节点访问寄存器和内存的方式。

## 1.5.2 基于Fabric的统一访问架构

### Ref节点与普通节点

- 选择一个通过PCIe连接Host的FPGA作为参考节点Ref，其他FPGA作为普通节点，通过板间链路接入Fabric。
- Ref承担Host请求的接入与响应返回；所有节点保留本地DUT、控制寄存器和内存。
- Host经Ref访问本地和远端节点，普通节点无需分别占用独立的Host PCIe连接。

### 统一的资源访问接口

- Host指定目标节点及其局部地址，Fabric将请求送达对应FPGA。
- 寄存器访问用于运行控制和状态查询，内存访问用于程序、模型数据及其他运行数据的读写。
- Driver对上层继续提供各分区的寄存器和内存对象，底层通过共享的Ref入口完成访问。
- 上层通过节点身份和资源地址选择访问目标，无需根据节点是否与Host直连而改变控制步骤。
- 该结构减少主机接口数量对扩展的约束；实际规模仍受板间互连、接入带宽和具体实现限制。

## 1.5.3 Fabric组件及统一访问过程

### 主要组件的职责

- **访问发起器（AccessInitiator）**：接收访问请求，将目标节点、地址和读写操作组织为Fabric请求，并匹配返回的响应。Ref侧发起器提供Host接入能力。
- **路由器（FabricRouter）**：根据目标节点，将请求和响应送往本地端点或板间链路，连接各节点的访问通路。
- **访问代理（AccessAgent）**：在目标节点接收请求，通过本地总线读写寄存器或内存，并返回执行结果。
- **板间链路与接口适配**：连接各节点Router，承载Fabric报文，将统一通信接口接到实际板级链路。
- 普通节点也具有面向节点侧请求的发起能力；本节以Host访问各FPGA为主线，组件说明围绕该过程展开。

### 一次远端寄存器读取

1. Host指定FPGA B及寄存器局部地址，通过PCIe将读取请求提交给Ref。
2. Ref的Initiator将请求转换为带有目标节点信息的Fabric报文。
3. Ref的Router将报文送往板间链路，FPGA B的Router将其投递给本地Agent。
4. Agent读取本地寄存器，生成包含读取值和执行状态的响应。
5. 响应经Fabric返回Ref，由Initiator完成对应的Host访问。

### 本地访问与内存访问

- 访问Ref自身时，请求在Ref内部完成投递和执行；Host仍使用相同的节点与地址访问方式。
- 内存访问采用相同的发起、转发、目标执行和响应返回关系，由Agent访问目标节点的本地内存。
- 上述组件共同提供统一访问能力，为前文的运行控制与状态管理提供远端资源访问基础。

## 1.5.4 阶段性实现与验证

### 统一访问通路的实现

- 已实现访问发起器、路由器和访问代理，并将其接入Ref与普通节点的Role结构，形成面向本地和远端寄存器、内存的访问通路。
- Driver提供面向各分区的寄存器和内存对象，通过共享Ref入口提交请求，为上层保留统一的访问方式。
- 已搭建双节点Role联合仿真环境，Host请求经Ref侧总线接口进入Fabric，再由目标节点执行。验证环境保留组件之间的实际RTL访问路径。

### 寄存器与内存访问验证

- **寄存器访问**：分别读取Ref与普通节点的身份、状态等寄存器，检查目标选择和返回值；通过可读写寄存器检查写入及回读结果。
- **内存访问**：向两个节点的内存写入不同数据并分别回读，检查访问是否到达正确节点、读取内容是否一致，以及写入是否影响其他节点。
- **组件协作**：结合请求与响应记录，确认远端访问经过Ref发起、跨节点转发、目标执行和响应返回，验证1.5.3所述访问过程。
- **访问异常**：检查无效目标或地址等访问能否返回错误，避免将失败请求报告为成功；正文只概括验证目标和结果。

### 阶段性结果与验证边界

- 依据实际记录，简要交代组件及Driver访问测试、双节点Role联合访问的完成情况；结果聚焦本地/远端寄存器和内存访问。
- 区分组件独立测试与完整访问通路的联合验证。已有组件或软件测试结果不能直接作为双节点统一访问已通过的证据。
- 联合验证结果需附节点配置、测试数据、比较方法及日志来源；尚未完成的项目保留待补充位置，不预填成功结论。
- Cosim结果与真实板卡验证分别说明；DUT运行、一致暂停及恢复重放等系统级实验集中在1.6展开。
