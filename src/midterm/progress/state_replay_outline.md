# 1.3 分布式状态提取、恢复与重放：详细大纲

本节聚焦REMUS在REMU基础上完成的两项扩展：划分控制与扫描链控制的交互，以及面向分区的状态组织和映射。REMU已有的寄存器与存储器扫描、Scanout/Scanin和软件波形重放作为技术基础简要交代，不分别展开为REMUS的工作。

章节收束为三个小节。原恢复、软件Replay两个小节并入1.3.2末尾，原1.3.5的功能验证调整为1.3.3。总大纲和TeX正文保持不变。

## 1.3.1 划分控制与扫描链控制的协同

**（1）多FPGA执行对原有控制方式的扩展**

- REMU已提供运行、暂停和扫描模式控制。REMUS引入跨分区传播后，模型交互完成并不代表一个DUT逻辑周期已经完成，还必须等待跨片组合逻辑传播结束。
- 因此，将划分控制机接入原有运行与扫描控制体系，使DUT逻辑时钟、周期计数、暂停状态和扫描模式采用一致的执行边界。

**（2）控制信息的双向交互**

| 交互方向 | 信息 | 作用 |
| --- | --- | --- |
| 扫描链侧运行控制→划分控制 | 运行使能、同步屏障请求 | 控制是否启动逻辑周期，并在一致暂停过程中约束传播阶段的推进 |
| 划分控制→扫描链侧运行控制 | 传播节点、逻辑周期完成信号、同步屏障确认 | 提供暂停边界与同步进度，使周期计数、步进控制和DUT状态更新对应同一逻辑周期 |

- 本地模型交互完成后，划分控制机组织跨片传播；最后一个传播节点完成后，才发出逻辑周期完成信号，驱动DUT时序状态更新及周期计数。
- 暂停请求与传播进度配合，在合法周期边界停止执行；同步请求和确认用于主机协调各分区。具体一致暂停算法引用1.2，不重复展开。

**（3）从一致暂停切换到扫描模式**

- 各分区完成一致暂停、相关模型空闲后，由主机协调进入扫描模式，启动各分区的局部扫描操作。
- 正常执行的时钟使能由逻辑周期完成条件控制；扫描时的访问由原有扫描使能控制。扫描消耗物理时钟周期，但不推进DUT逻辑周期及其计数。
- 主机等待各分区扫描完成后退出扫描模式，随后保持暂停或重新启动逻辑执行。由此将REMU已有的扫描操作接入多FPGA执行流程。

## 1.3.2 分布式状态提取与全局检查点组织

**（1）分区扫描数据的本地存储与统一收集**

- 各分区复用REMU已有的局部扫描结构，导出的扫描数据先存储在各自FPGA上的内存中，由主机按分区读取并保存。
- 各FPGA独立完成局部扫描，无需将多个FPGA串接为一条跨片扫描链。各分区到达同一个逻辑周期并保持暂停后，先后读取的数据仍对应同一逻辑时刻。
- 主机以共同逻辑周期组织各分区数据，形成全局检查点（Global Snapshot）。各分区可以保留独立数据文件，全局一致性来自共同周期与状态对应关系，不要求拼接成单一文件。

**（2）面向分区的状态映射元数据**

- 单FPGA下的扫描布局不足以标识多FPGA状态所在的位置。REMUS在编译过程中分别记录各分区的扫描布局，并合并为全局状态描述。
- 元数据建立“分区标识→局部扫描位置→逻辑状态对象”的对应关系，包含分区归属、状态层次名称、位宽、片段偏移、扫描顺序及存储器形状等信息。
- 解析扫描数据时，先按分区定位数据，再根据扫描布局提取位段，将其对应到统一的寄存器与存储器状态视图；反向操作则形成各分区的扫描镜像。
- 状态名称与生成的重放RTL层次保持对应，包括划分带来的层次变化。检查点、状态元数据和重放RTL使用配套编译产物。

**（3）检查点包含的数据及其关系**

| 内容 | 作用 |
| --- | --- |
| 各分区扫描数据 | 保存局部寄存器、RTL存储器及扫描覆盖的模型状态；先写入各自FPGA内存，再由主机收集 |
| 模型内存数据 | 保存程序、数据等存储模型内容，与扫描数据共同构成后续执行所需状态 |
| 状态映射元数据 | 描述各分区扫描布局及其与逻辑状态的对应关系，支持统一解码和按分区写回 |
| 周期与区域信息 | 记录检查点逻辑周期、分区数量和内存区域归属，组织同一时刻的数据集合 |
| 受管理的输入记录 | 记录输入值及变化周期，为检查点之后的输入重现提供依据；后续输入序列区别于单时刻状态快照 |

- 分布式检查点的关键是共同周期、状态覆盖和分区映射三者一致：既能够定位每份局部数据，也能够解释其在完整设计中的含义。
- 数据传输的Fabric路由与Host访问细节留到后续运行控制和状态传输章节。

**（4）通过分区映射复用REMU的恢复与重放能力**

- REMUS补充分区归属与状态映射后，将各分区数据接入REMU已有的检查点处理流程：按分区写回并Scanin，可用于FPGA上的Restore和Replay；解码为统一逻辑状态，可供软件RTL重放及波形观测使用。
- 本节用上述关系说明多FPGA扩展如何承接既有能力，不展开Scanout/Scanin状态机、软件加载器或波形输出原理。复用仍以1.3.1的控制协调、配套状态数据及已有输入和模型机制为基础。

## 1.3.3 功能验证与阶段性结果

**（1）分布式状态提取与映射验证**

- 以PicoRV32和KMH为DUT，在Cosim中使划分后的设计与单体参考执行至相同逻辑周期。
- 对一致暂停后的分区执行完整Scan Dump、数据落盘及解码，通过扫描导出的内部状态与单体参考进行比较，结果相同。
- 这一结果验证了控制协同、分区状态提取及状态映射组成的完整路径。1.2侧重证明暂停周期与状态正确，本节侧重说明这些状态通过分布式扫描数据获得。

**（2）已有恢复与重放能力在分区状态上的验证**

| 验证内容 | 作者已确认的结果 |
| --- | --- |
| 从非零周期检查点在逻辑仿真软件中进行Replay | 后续运行结果符合预期 |
| 从非零周期检查点在FPGA上进行Replay和Restore | 后续运行结果符合预期 |
| 继续运行后再次保存检查点 | 检查点数据符合预期 |

- 这些实验用于验证分区检查点能够被已有恢复与重放流程正确使用，不将被复用的基础功能列为新增机制。
- 实验材料补齐各组DUT、分区数量、检查点周期、后续执行区间和实际比较对象；现有确认不扩写为逐信号波形已经完成对照。
