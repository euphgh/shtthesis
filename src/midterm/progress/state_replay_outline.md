# 1.3 分布式状态提取、恢复与重放：详细大纲

本节按“**状态表示→状态提取→恢复与重放→功能验证**”介绍REMUS的多FPGA状态管理。重点是分区状态的统一组织以及扫描控制与跨分区执行的协同；REMU已实现的扫描、状态恢复和输入重放仅作必要交代，不展开其内部原理。

## 1.3.1 分布式状态模型与全局检查点设计

**（1）REMU状态管理基础与多FPGA问题**

- REMU通过扫描链保存DUT全部寄存器（FF）和SRAM状态，并保存Memory数据与按DUT逻辑周期记录的Input变化。Scan Chain与Memory用于恢复执行状态，Input记录用于重现外部输入。
- 将DUT划分到多个FPGA后，扫描状态分散在各分区；当前REMUS仍沿用REMU的Memory与Input机制，并将它们集中部署在一块FPGA上。
- REMUS新增的要求是：**各分区状态属于同一DUT逻辑周期**，并且**局部扫描数据能够对应到未划分DUT中的逻辑状态对象**。前者由1.2的一致暂停保证，后者由分区状态映射解决；不将REMU已有的扫描覆盖能力重新作为研究问题。

**（2）Global Snapshot的数据组织**

| 组成 | 作用 |
| --- | --- |
| 各分区Scan Chain文件 | 分别保存所在FPGA的寄存器和SRAM状态 |
| Memory数据 | 保存恢复后继续执行所需的内存状态 |
| Input变化记录 | 保存按逻辑周期标记的完整输入历史，供恢复初始Input和重放后续变化 |
| 周期标识与状态映射 | 关联同一周期的分区数据，并说明它们对应的原始DUT状态 |

- Global Snapshot按共同逻辑周期关联各分区文件和配套信息，不要求把所有扫描数据合并成单一文件。
- Input记录是重放所需的配套数据：**检查点不单独保存当时各Input的取值**，恢复时由Driver或软件Replay根据完整输入记录确定初始值。

**（3）局部扫描布局与全局状态映射**

- REMUS在编译阶段记录各分区扫描布局，建立“**分区标识→局部扫描位置→未划分DUT逻辑对象**”的对应关系，并保存必要的位宽、扫描位置和层次等信息。
- 该映射使软件RTL重放能够将分区扫描数据解码并加载到相应逻辑状态；FPGA恢复则可以直接利用匹配的分区扫描布局将数据写回对应FPGA。状态映射及重放RTL需与保存检查点时的编译产物配套。
- 本节只解释数据组织与映射原理，具体扫描和收集过程放在1.3.2。

## 1.3.2 分布式状态提取与扫描控制协同

**（1）划分控制与运行控制的协同**

- REMU已有运行、暂停、定步和扫描模式控制；REMUS引入LI-TDM后，本地模型完成交互不代表整个DUT逻辑周期已经结束。
- 因此，将划分控制机的跨分区传播完成信号接入运行控制，使DUT状态更新、周期计数和定步执行采用一致的周期完成条件。双方还交换运行使能、同步屏障请求与确认等信息，以支持1.2节的一致暂停。

**（2）一致暂停后进入扫描**

- 主机依照1.2节完成全局一致暂停，确认所有分区停在共同逻辑周期，并满足扫描所需条件后，才切换到扫描模式；接收屏障确认本身不代表最终暂停完成。
- 各分区复用REMU已有扫描机制独立导出状态。扫描使用物理时钟，不增加DUT逻辑周期计数。

**（3）局部状态导出与主机汇聚**

- 各FPGA将局部Scan Dump数据写入本地DDR；主机随后分别读取各分区数据，保存为独立扫描文件，再结合1.3.1定义的周期信息和映射组织Global Snapshot。
- 一致暂停后各分区可先后完成扫描与收集，无须在同一物理时刻返回数据。Host分布式控制和DDR访问的具体实现留到1.5节介绍。

## 1.3.3 基于全局检查点的状态恢复与确定性重放

**（1）从Global Snapshot恢复状态（Restore）**

- Restore是Replay的第一步。硬件恢复时，将各分区扫描文件送回对应FPGA，复用REMU的Scanin写回寄存器和SRAM；软件恢复时，通过全局映射将扫描状态加载到配套的RTL仿真对象。
- 两条路径均需恢复Memory和检查点时刻的初始Input值。初始Input由完整的输入变化记录推导，不依赖独立保存的Input快照。

**（2）恢复后的确定性重放（Replay）**

- Restore完成后，系统从检查点继续执行，并按记录中的DUT逻辑周期重新施加Input变化。硬件与软件分别沿用REMU既有的Step控制和VPI定时输入机制；软件RTL重放还可用于观察内部波形。
- 这一部分只说明分布式检查点如何接入REMU的Replay流程，不展开Step、VPI的内部实现。重放正确性需要结合实际输出或状态对照验证，不能仅凭成功加载检查点推定。

## 1.3.4 功能验证与阶段性结果

**（1）分布式状态提取与映射验证**

- 以PicoRV32和香山昆明湖（KMH）为DUT，在多分区Cosim一致暂停后执行Scan Dump、保存与解码，并同周期对照未划分DUT的单体RTL状态。
- 已有实验在实际比较的内部状态范围内结果相同。正式正文需补充DUT配置、暂停周期、比较范围和实验依据，不扩写为全部状态的逐周期等价。

**（2）非零周期检查点的Restore与Replay验证**

| 测试内容 | 已确认结果 |
| --- | --- |
| 软件RTL Replay及FPGA Replay/Restore | 从非零周期检查点继续执行，结果符合预期 |
| 继续运行后再次保存检查点 | 保存的数据符合预期 |

- 上述测试的DUT、平台、检查点周期及比较对象需分别补齐；不假定已完成全部内部信号波形对照，也不将REMU继承功能当作新增贡献。

**（3）后续实验**

- 根据实际测试补充Scan Dump规模、导出与收集时间、资源开销以及更大规模DUT或分区配置的验证。未完成的实验保留为计划，不预写结果。
