# 1.3 分布式状态提取、恢复与重放：详细大纲

本节按照“**分布式状态表示→状态提取→状态恢复与确定性重放→功能验证**”展开。首先交代REMU已有的状态保存与重放基础，以及DUT划分后产生的新问题；随后介绍REMUS如何统一组织分区状态、协调扫描并收集数据；最后说明同一全局检查点如何用于FPGA和软件RTL中的Restore与Replay。保持中期报告定位，不重复介绍REMU的Scanout/Scanin状态机和软件重放器内部算法。

**研究边界**：REMU已对DUT全部寄存器（FF）与SRAM插入扫描结构，并配套保存Memory和Input。REMUS沿用这一覆盖能力，重点解决多FPGA情形下的两项新增要求：**各分区状态对应同一个DUT逻辑周期**，以及**分区扫描数据能够映射到未划分DUT中的逻辑状态对象**。这里不把REMU已解决的扫描状态覆盖问题重新列为REMUS的独立研究贡献。

四个小节标题与总大纲`src/midterm/outline.md`一致。仓库中的`state_replay.tex`已经具有四小节结构，但正文仍需按本版大纲进一步修订；本次不修改TeX正文。

## 1.3.1 分布式状态模型与全局检查点设计

**（1）REMU状态表示与多FPGA带来的变化**

- 从后续执行需要哪些数据引入REMU的三类信息：① **Scan Chain**保存DUT全部FF、SRAM的扫描状态；② **Memory**保存DUT使用的内存模型状态或内存修改数据；③ **Input**记录受管理外部输入随DUT逻辑周期发生的变化。REMU以相应文件保存这三类信息，并通过Restore及Replay使用它们。
- 区分两类信息的作用：Scan Chain和Memory用于恢复检查点时刻的执行状态；Input包含输入变化的完整记录，用于推导所选检查点的初始输入值，并在继续执行时重现后续变化。**Global Snapshot不单独保存检查点时刻各Input的当前值**。
- 将DUT划分到多个FPGA后，原来集中在一块FPGA上的时序状态分别落到不同分区；每块FPGA只具有其局部FF、SRAM的扫描数据。REMU单FPGA的Scan Dump不能直接导出其他FPGA中的状态。
- REMUS在每个FPGA部署本地扫描控制逻辑，独立把本分区状态导出到对应的DDR；Host再将多片FPGA的扫描数据收集为`scan_chain0`、`scan_chain1`等分区文件。该数据路径在1.3.2介绍，Host跨FPGA控制与访问机制在1.5节展开。
- **当前实现边界**：Memory与Input继续复用REMU的管理方式，固定部署在一块FPGA上；多FPGA扩展主要发生在Scan Chain的分布式保存、收集及映射，而不是把三类信息都改造成对称的分布式存储。
- 提出REMUS所需解决的两个问题：不同分区导出的状态必须属于同一DUT逻辑周期（由1.2的一致暂停保证）；收集到Host的多个局部扫描文件必须能够对应回**原始未划分DUT**的寄存器、SRAM等逻辑对象（由分区状态映射解决）。两者缺一不可，但不重新论证REMU的扫描覆盖能力。

**（2）Global Snapshot的数据组织**

- 以统一的DUT逻辑周期为索引，组织分区扫描文件、Memory数据、完整Input记录及其配套描述信息，形成Global Snapshot。各分区文件保持独立，不需要把所有扫描比特合并为单一文件。
- 说明“检查点时刻的执行状态”与“支持从检查点重放的配套记录”的区别；Input记录可以覆盖检查点前后的事件，以便重建检查点处的输入值及之后的输入变化。

| 类别 | 数据 | 作用与组织方式 |
| --- | --- | --- |
| 检查点状态 | `scan_chain0`、`scan_chain1`、…… | 各FPGA扫描链导出的局部FF、SRAM状态，按分区保存 |
| 检查点状态 | Memory数据 | 沿用REMU机制，保存所需内存模型状态或修改数据；当前由一块FPGA管理 |
| 状态描述 | 分区标识、局部扫描布局、逻辑状态映射 | 说明每份扫描数据对应哪块FPGA及未划分DUT中的哪些状态对象 |
| 时间信息 | 共同DUT逻辑周期 | 关联同一逻辑时刻的扫描与内存状态，并作为恢复及重放的起点 |
| 重放配套记录 | 完整Input变化记录 | 按DUT逻辑周期记录输入变化；用于计算检查点处的初始输入值并重放后续事件，**不直接存储该时刻的输入值快照** |

- 强调Global Snapshot的“全局”来自**共同周期与统一逻辑映射**，而非“所有数据来自同一FPGA”或“必须合并为一个二进制文件”。
- 输入变化记录属于检查点配套数据，但不与某个时刻的扫描状态混为同类；恢复与重放软件应按记录内容及既有周期边界约定重建输入状态。
- 状态文件、映射元数据和重放RTL必须配套使用，避免将不同编译配置下的局部扫描布局混用。

**（3）局部扫描布局与全局逻辑状态映射**

- 编译阶段为各分区记录局部扫描布局，并将其与未划分DUT的逻辑对象建立对应关系，概括为“**分区标识→分区内扫描位置→原始DUT逻辑状态对象**”。
- 映射描述包含分区归属、逻辑状态名称、位宽、扫描顺序、片段偏移，以及SRAM字宽、深度等结构信息。由于划分和转换可能改变RTL物理层次，还需维护原始逻辑对象与实际软件重放RTL对象之间的配套关系。
- 用一条寄存器或SRAM的示意映射解释：原始DUT的某个状态对象被分配至FPGA B，位于其局部扫描数据的特定片段；Host根据分区标识和局部布局找出对应比特，并解释为原始DUT的相应状态。示例不使用未经核实的真实偏移。
- **软件RTL Restore**需要将多个分区扫描比特解码、组合并加载到对应的逻辑仿真对象。**FPGA Restore**若使用相同的分区设计及扫描布局，可以按分区将原扫描数据送回对应FPGA完成Scanin，不必先把每一位解码为原始DUT名称再重新编码。
- 本小节只解释状态布局和数据的逻辑关联，不展开Scan Dump执行顺序、DMA操作或Host下发指令的细节。

## 1.3.2 分布式状态提取与扫描控制协同

**（1）划分控制与运行/扫描控制的交互**

- REMU具备运行、暂停、定步执行和扫描模式。REMUS引入LI-TDM跨片传播后，本地模型完成交互不等于一个DUT逻辑周期完成；只有完成当前周期所需的分区间组合数据传播，才可以更新DUT时序状态。
- REMUS将划分控制机的逻辑周期完成条件与原有运行控制连接，使DUT状态更新、周期计数及剩余Step数采用相同的完成边界。划分控制机还向运行控制提供传播进度与同步屏障确认。
- 明确组件职责：**运行与模式控制**负责运行使能、周期计数、屏障请求及扫描模式协调；**划分控制**管理跨分区传播及周期完成条件；**局部扫描控制**复用REMU已有的状态移位与SRAM扫描机制，不将三者混为一个扫描状态机。

| 交互方向 | 信息 | 用途 |
| --- | --- | --- |
| 运行与模式控制→划分控制 | 运行使能、同步屏障请求 | 约束逻辑周期推进并启动暂停协调 |
| 划分控制→运行与模式控制 | 传播进度、逻辑周期完成信号、屏障确认 | 提供周期完成条件及稳定的屏障采样位置 |

**（2）全局一致暂停后进入扫描**

- 引用1.2.2的暂停流程：Host先请求接收屏障，稳定读取各分区周期计数，设置共同目标周期及剩余步数，再解除屏障并等待所有分区在同一周期最终停止。
- **接收屏障确认仅表示稳定采样位置，不代表全局一致暂停已完成。** 必须在各分区到达同一目标周期、停止正常推进并满足模型空闲等扫描条件后，Host才能统一协调进入扫描模式。
- 正常运行由LI-TDM周期完成条件驱动DUT逻辑状态更新；扫描状态由REMU原有扫描使能与扫描协议管理。扫描消耗FPGA物理时钟周期，但不推进DUT逻辑周期计数。
- 各分区的扫描操作可独立执行，不要求在相同的物理时钟周期完成；最终导出的状态依照原有扫描协议对应同一DUT逻辑时刻。

**（3）局部Scan Dump、DDR缓存与Host汇聚**

- 每块FPGA本地的扫描链与扫描控制逻辑将全部局部FF、SRAM状态按局部布局导出至该FPGA的DDR；不建立跨FPGA串接的单一扫描链。
- Host在全部分区完成扫描后（或在保持正确性前提下按既有控制流程收集），通过DMA分别读取各FPGA的DDR扫描缓冲，并保存为`scan_chain0`、`scan_chain1`等分区文件。
- 例如FPGA A和FPGA B都停在周期$T$，虽然两片DDR的扫描数据在不同物理时刻被读取，只要扫描和读取流程不引入新的DUT逻辑周期推进，文件仍分别表示周期$T$的对应局部状态。
- Host将局部文件与Memory、Input文件及映射元数据关联，形成1.3.1定义的Global Snapshot。Host如何跨节点发起控制、如何访问不同FPGA上的DDR由1.5节介绍，本节仅保留解释状态提取所必需的数据路径。
- 小节结尾自然衔接1.3.3：局部数据已经能够完整收集，但恢复到FPGA或软件RTL时，还需要按映射选择加载目标，输入记录也必须按照逻辑周期重新施加。

## 1.3.3 基于全局检查点的状态恢复与确定性重放

**总体关系：Replay以Restore为第一步。** Restore负责恢复指定检查点时刻的DUT状态以及初始Input；Replay在此基础上重现检查点之后按逻辑周期记录的Input变化，并继续执行DUT。两条运行路径共享相同的状态和Input事件含义，仅具体加载与事件调度方式不同。

**（1）从Global Snapshot恢复到FPGA或软件RTL（Restore）**

- **硬件Restore**：按分区归属把对应`scan_chainN`文件通过Host送回正确FPGA，利用REMU已有的Scanin写回局部FF、SRAM；恢复Memory及必要的模型状态，并在各分区完成恢复后统一恢复执行条件。同一分区的扫描布局与保存时应保持匹配。
- **软件Restore**：读取多个局部Scan Dump，依据全局映射定位到原始未划分DUT的逻辑状态，再加载到配套重放RTL的软件仿真对象；同时恢复Memory等状态。此路径需要状态解码及逻辑对象映射，区别于硬件直接按分区Scanin。
- **初始Input的恢复**：Global Snapshot不包含每个Input在检查点时刻的独立取值快照，但保存完整Input变化记录。Host Driver与软件Replay VPI分别根据输入事件记录和REMU既有的周期边界约定，确定所选检查点对应的Input初始值，并在继续执行前恢复这些值。
- Restore完成的判断不只看单一FPGA或单个文件是否写入，还要确认各分区及Memory、Input等需要恢复的内容均已正确就位；具体Host指令与数据搬运留在1.5节。

**（2）Input事件记录与确定性重放的共同逻辑**

- REMU按**DUT逻辑周期**记录受管理Input的变化。将记录视为按时间排列的事件序列，每条事件包含所属逻辑周期及输入变化内容；Replay从选择的检查点周期$C_0$开始，先恢复该时刻的Input取值，再处理之后的事件。
- 两个环境共用同一逻辑时间轴：输入变化必须在记录指定的DUT逻辑周期生效，而不能按FPGA实际物理时钟数或Host命令到达时间重新解释。
- 对于示意事件：检查点位于周期1000，下一次Input变化记录在周期1024，则从检查点到该事件的逻辑周期偏移为$1024-1000=24$。该偏移既可用于硬件Step计算，也可映射为软件仿真时间回调。实际在周期边界上的赋值顺序遵循REMU原有输入记录和执行约定，不凭示例额外假定早一拍或晚一拍。
- 区分**初始Input重建**与**检查点之后的Input事件重放**：前者可利用检查点之前的完整历史记录推导当前值，后者依事件时间依次施加输入变化。这说明为何保存完整Input记录，而不要求额外保存每个检查点的Input值文件。

**（3）硬件Step与软件VPI的Replay执行方式**

| 环境 | 输入变化的调度方法 | 与DUT逻辑时间的对应关系 |
| --- | --- | --- |
| FPGA硬件Replay | Host按Input事件的逻辑周期排序，利用REMU Step运行到下一个事件周期，通过Input控制寄存器设置新值，再继续Step至后续事件 | 每段Step对应从当前DUT逻辑周期到下一事件周期的差值，不依赖跨FPGA实际耗费的物理时钟数 |
| 软件RTL Replay | 利用VPI的`vpi_register_cb`注册基于仿真时间的回调，时间采用`vpiSimTime`；回调触发时更新相应Input值 | 软件仿真时间的单位刻度与DUT逻辑周期刻度对应；事件在回放窗口中的时间为记录周期减去检查点基准周期 |

- 对于上述1000→1024的例子，硬件从恢复周期执行**24个DUT逻辑周期**，然后通过相应Input寄存器写入新值；软件在相对仿真时间**24**处安排对应的Input更新回调。
- 若后面仍有事件，两种路径分别重复“Step至事件周期→写入Input”和“注册/触发对应仿真时间回调→更新Input”，直到完成目标重放区间。运行到最后一个事件以后，还可以继续执行至所需观测周期。
- 软件RTL Replay在正常逻辑仿真调度中可以获取内部波形，用于追踪硬件长时间执行中发现的问题；硬件路径则保持REMU原有的定步控制及输入寄存器写入机制。
- 不把Restore后能够继续运行直接等同于已经验证完全确定性Replay；实验需要以实际比较的程序输出、检查点状态或周期级事件说明证据范围。
- **研究定位**：上述Step调度、输入寄存器控制与VPI输入回调属于REMU已有机制。REMUS的新增工作是使分布式Global Snapshot和跨FPGA协调能够正确接入两条路径，不把继承机制重复列为独立贡献。

## 1.3.4 功能验证与阶段性结果

**（1）分布式Scan Dump与全局状态映射验证**

- 以PicoRV32和香山昆明湖（KMH）为已确认DUT，在多分区Cosim中执行全局一致暂停、局部Scan Dump、DDR落盘、Host收集和映射解码；未划分DUT的单体RTL仿真在相同逻辑周期提供参考状态。
- 已有测试在**实际比较的内部状态范围**内结果相同，能够支持已测试的跨FPGA暂停、局部扫描与逻辑状态映射路径。尚不能据此推定所有寄存器、SRAM的每一位在所有周期均已完成对照。
- 补充真实材料：DUT版本及程序、分区数量和配置、暂停周期、对照状态对象和范围、解码/对照方式、日志或波形证据。

**（2）非零周期检查点的Restore与Replay验证**

| 已测试项目 | 已确认的阶段性结果 | 后续需要补充的验证依据 |
| --- | --- | --- |
| 非零周期检查点的软件RTL Replay | 继续运行结果符合预期 | DUT、仿真器、检查点周期、Input事件及比较对象 |
| 非零周期检查点的FPGA Replay及Restore | 继续运行结果符合预期 | DUT、板卡/分区配置、Step和Input控制场景、比较对象 |
| 恢复后继续运行并再次保存检查点 | 再次保存的检查点数据符合预期 | 再次检查点周期、具体比较范围及参考结果 |

- 上述测试并不默认使用同一DUT、同一负载或覆盖所有输入变化场景。现有结果证明分区数据能够接入已有恢复与重放流程，但不得直接扩写为完整的逐信号、逐周期等价。
- 进一步补充针对Input Replay的验证：检查点初始Input是否从完整记录正确恢复，硬件Step事件周期与软件VPI回调时刻是否对应，连续多次输入变化时是否保持正确的事件顺序。**这些属于后续需核实/补充的验证项目，不能在取得记录前写成已经全部通过。**
- 明确区分程序最终输出正确、选定内部状态一致和周期级事件/波形一致三类证据及其适用范围。

**（3）后续实验与评价**

- 在实际测量基础上补充Scan Dump数据量、DDR导出及Host收集耗时、状态映射/加载成本和资源开销；评估不同DUT及分区数量下的变化。
- 扩大非零周期Restore/Replay的负载和输入变化场景，对照所选时间区间的关键状态或周期级事件。对未完成的性能与规模实验保留计划，不编造结论。
