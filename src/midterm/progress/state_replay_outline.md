# 1.3 分布式状态提取、恢复与重放：详细大纲

1.3按“**分布式状态模型→状态提取→状态恢复与重放→功能验证**”组织。REMUS重点研究REMU向多FPGA扩展时的控制协同、状态归属与全局检查点组织；REMU已有的Scanout/Scanin、模型状态管理及软件RTL重放仅作为技术基础，不重复讨论其内部算法。

本文件与总大纲`src/midterm/outline.md`采用相同的四小节结构。**本轮不修改`state_replay.tex`**；它目前仍保留旧的三小节结构，后续撰写正文时需要同步。

## 1.3.1 分布式状态模型与全局检查点设计

**（1）分布式状态的定义与研究问题**

- 原始DUT的状态包含寄存器、RTL存储器等时序状态；完整恢复与继续执行还可能需要外部存储模型及其他必要的环境状态。
- 电路划分后，状态分布在不同FPGA及其关联的模型中。单个Scan Dump只保存局部数据，无法直接说明各比特对应原始DUT的哪个逻辑对象。
- 全局状态表示必须建立同一个有效逻辑周期的时间边界、覆盖必要状态，并能够将局部状态映射到完整逻辑设计；一致暂停解决时间边界，但不自动保证状态覆盖。

**（2）局部扫描布局与全局状态映射**

- REMUS在编译阶段为每个分区记录扫描布局，再合并为全局状态映射。关系可表示为“分区标识→局部扫描位置→逻辑状态对象”。
- 描述信息包含分区归属、状态层次名称、位宽、扫描顺序、片段偏移，以及存储器字宽和深度等；检查点与相关编译产物、重放RTL必须配套。
- 可举某个逻辑寄存器部署在FPGA B中的概念例子，说明局部扫描比特如何定位到逻辑状态；示例名称和偏移不作为实测数据。
- 从扫描比特到逻辑状态用于解码，从逻辑状态反向定位分区扫描位置用于恢复写回。

**（3）Global Snapshot的数据组织**

| 类型 | 数据 | 作用 |
| --- | --- | --- |
| 检查点时刻的动态状态 | 分区扫描数据 | 保存扫描覆盖的局部寄存器、RTL存储器及相关状态 |
| 检查点时刻的动态状态 | 模型内存等必要状态 | 保存继续执行所需的程序、数据和模型状态；核对与扫描数据的覆盖范围 |
| 描述与索引 | 状态映射、扫描布局、分区及区域信息 | 定位并解释数据，支持按分区恢复与统一解码 |
| 时间标识 | 共同DUT逻辑周期 | 关联同一逻辑时刻的各份局部状态 |
| 重放配套数据 | 检查点后的受管理输入记录 | 重现后续输入变化，不属于检查点瞬间的动态状态 |

- Global Snapshot是具有统一时间与状态映射关系的数据集合，允许多个独立分区文件，不要求合并成单一二进制文件。
- 核心条件是**周期一致、必要状态完整、映射正确**。数据传输采用的Fabric路由与Host接口留到1.5节介绍。

## 1.3.2 分布式状态提取与扫描控制协同

**（1）运行控制与划分控制的交互**

- REMU已有运行、暂停、步进与扫描模式；REMUS增加跨分区传播后，单纯的本地模型交互完成不再等同于完整DUT逻辑周期结束。
- 划分控制机输出传播进度、逻辑周期完成信号和屏障确认，运行与模式控制据此管理DUT更新、周期计数及剩余步数。局部扫描移位由独立扫描控制逻辑负责。

| 交互方向 | 信息 | 用途 |
| --- | --- | --- |
| 运行与模式控制→划分控制 | 运行使能、同步屏障请求 | 约束周期推进并发起暂停协调 |
| 划分控制→运行与模式控制 | 传播进度、周期完成信号、屏障确认 | 提供一致的周期完成条件与稳定采样位置 |

- 只有LI-TDM完成当前逻辑周期的必要传播，才更新DUT状态及逻辑周期计数，避免各控制模块对周期边界产生不同解释。

**（2）一致暂停后启动扫描**

- 主机执行1.2.2节的全局暂停协议：在接收屏障处采样稳定进度，计算共同目标，配置剩余步数，解除屏障并等待最终暂停。
- **接收屏障确认≠最终一致暂停完成**，不能收到屏障确认就进入扫描。需等待各分区到达目标逻辑周期并满足相关模型空闲等扫描条件。
- 正常运行时按DUT逻辑周期完成条件推进状态；扫描模式时由扫描使能访问状态，消耗物理时钟但不增加DUT逻辑周期计数。
- 扫描完成后退出扫描模式，保持暂停或恢复正常运行；导出数据有效性依赖REMU既有扫描协议，不额外声称扫描移位不改变任何物理存储位。

**（3）局部Scan Dump与Host收集**

- 每个分区保留独立扫描结构，Scan Dump先写入所在FPGA的内存，再由Host逐分区读取并保存，不需要将所有FPGA串为跨片扫描链。
- FPGA A和B可在同一个DUT逻辑周期$T$暂停，却在不同的物理时刻完成扫描和传输；在暂停和扫描协议约束下，两份数据仍对应周期$T$的有效状态。
- Host按共同逻辑周期及分区归属组织文件，并用1.3.1的状态映射形成全局检查点。

## 1.3.3 基于全局检查点的状态恢复与确定性重放

**（1）FPGA状态恢复（Restore）**

- 按全局映射定位每个状态片段所在分区，生成对应扫描镜像，复用REMU Scanin写回必要的DUT状态。
- 同时恢复必要模型状态，确保可以从检查点周期继续执行。本文重点讨论多分区数据定位和协调，不重复REMU原有Scanin状态机。

**（2）软件RTL状态加载**

- 按分区读取Scan Dump，再依据全局状态映射解码出逻辑寄存器、存储器等状态，加载到对应的重放RTL仿真对象。
- 说明这与FPGA的Scanin是两条不同恢复路径；状态名称可能因划分与转换发生变化，因此元数据必须与重放RTL配套。

**（3）确定性重放与波形观测**

- 状态恢复完成后，从检查点所对应的逻辑周期继续执行，并复用REMU受管理输入记录机制重现必要的输入变化。
- 在FPGA上恢复并继续执行，与软件RTL中重放并导出内部波形，应分别说明数据加载方式；不将FPGA Restore、FPGA Replay及软件Replay视作三个互不相关的新机制。
- 完整重放依赖必要状态覆盖、输入及环境行为可再现；不得用“后续输出符合预期”替代逐信号、逐周期等价证明。

## 1.3.4 功能验证与阶段性结果

- 已有测试在实际比较的内部状态范围内结果相同，支持控制协调、分区扫描和映射解码的完整路径；不推定所有内部对象均已逐位比较。

**（2）非零周期检查点的Restore/Replay**

| 已验证的项目 | 已确认结果 |
| --- | --- |
| 从非零周期检查点执行软件RTL Replay | 后续运行结果符合预期 |
