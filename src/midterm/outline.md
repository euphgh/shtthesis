# 中期报告大纲

## 第一章 课题研究进展与阶段性成果

### 1.1 研究目标与总体技术路线回顾

#### 1.1.1 从多FPGA原型验证到可观测的多FPGA仿真加速

- 随着SoC规模和复杂度持续提升，系统级验证需要覆盖更大的硬件状态空间，并运行固件、操作系统和应用程序等长时间软件负载。传统RTL软件仿真可观察性强，但执行速度难以支撑大规模、长时间验证。
- FPGA原型验证通过将RTL设计映射到可编程逻辑上直接运行，可显著提升执行速度；当设计超过单片FPGA容量后，可进一步通过电路划分和跨片互连部署到多个FPGA。
- 多FPGA原型验证主要解决“大规模设计如何运行”的问题，但内部状态观测能力有限。常规Trace或片上逻辑分析通常只能记录有限信号和有限时间窗口，难以获得目标时刻的完整内部状态。
- 基于Scan Dump的硬件仿真可在确定逻辑周期暂停DUT，导出完整时序状态形成Snapshot，并通过状态恢复和确定性重执行生成目标时间段的内部波形。
- 将Scan Dump扩展到多FPGA后，必须保证所有FPGA在同一DUT逻辑周期一致暂停，并正确提取、组合各节点状态。本课题由此将多FPGA系统从“能够运行”扩展为“能够暂停、观测、恢复和重放”的硬件仿真加速系统。

多FPGA原型验证与本课题所面向的多FPGA仿真加速在能力侧重点上存在如下区别：

| 能力 | 多FPGA原型验证 | 基于Scan Dump的多FPGA仿真加速 |
| --- | --- | --- |
| 大规模RTL部署 | 支持 | 支持 |
| 高速运行软件负载 | 支持 | 支持 |
| 跨FPGA周期精确执行 | 以功能正确为目标 | 暂停、状态提取和重放的基础 |
| 全系统一致暂停 | 通常不是核心能力 | 核心能力 |
| 完整时序状态提取 | 能力有限 | 核心能力 |
| Snapshot/Restore | 能力有限 | 核心能力 |
| 确定性重放与波形恢复 | 能力有限 | 核心能力 |

#### 1.1.2 多FPGA状态提取与可重放仿真的关键问题

**（1）分布式状态的一致暂停与全局提取**

- 单FPGA中，DUT状态集中在同一物理器件内；多FPGA中，寄存器、存储状态等时序状态被分散到不同节点。
- 完整Snapshot必须由所有FPGA在同一DUT逻辑周期的状态组成。若各节点停止在不同周期，组合结果不对应原始RTL的任何真实全局状态，无法用于正确恢复和重放。
- 因此，系统需要先实现全局周期一致暂停，再分别导出各FPGA状态，并按原始DUT的状态映射关系聚合为全局Snapshot。
- “一致暂停—局部导出—全局聚合”构成多FPGA状态提取的核心流程。

```text
         DUT logical cycle N
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
     FPGA 0    FPGA 1    FPGA N
        │         │         │
        └── Global Pause ───┘
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
      Dump 0    Dump 1    Dump N
        └─────────┼─────────┘
                  ▼
          Global Snapshot
```

**（2）跨FPGA执行过程的周期精确性**

- 原始RTL在统一逻辑时钟下执行；划分后，组合路径可能跨越多个FPGA，跨分区信号需要经过实际物理链路传输。
- 因此，FPGA物理时钟不能直接等同于DUT逻辑时钟。系统必须等待当前逻辑周期所需的跨分区数据全部传播完成，再统一推进下一周期。
- 对于连续跨越多个分区的组合路径，一个逻辑周期可能需要多轮跨FPGA通信。分区传播深度（Partition Propagation Depth，PPD）直接影响通信轮次和仿真性能。
- 周期精确执行既是功能正确的基础，也是定义全局一致暂停点的前提。

**（3）多FPGA状态传输、恢复与统一控制**

- 多FPGA仿真系统不仅需要Run和Reset，还需要统一支持Pause、Step、Dump、Restore、Replay等状态管理操作。
- 随着FPGA数量增加，控制命令需要从统一入口分发到各节点，并在一致的逻辑周期边界生效。
- Scan Dump产生的分布式状态需要汇聚为全局Snapshot；恢复时再将状态分发回对应FPGA。
- 因此，系统需要统一的控制平面和状态传输路径，使多个物理节点对用户表现为一个仿真器。

**（4）面向多FPGA仿真的高质量自动化电路划分**

- 多FPGA仿真首先需要将超出单FPGA容量的RTL设计划分为多个可部署分区，并满足各FPGA的资源约束。
- 划分结果需要兼顾资源平衡、Cut Size和PPD。前者决定资源利用，Cut Size影响跨片通信量，PPD影响一个逻辑周期所需的通信轮次。
- 划分粒度也会影响上述指标，不同粒度下的划分对象、模块边界和图规模均不同。
- 面向通用RTL设计，划分流程还应减少人工指定边界和针对具体DUT的手工修改，实现自动化资源分析、划分和子设计生成。

其处理过程可概括为：

```text
RTL Design
    │
    ▼
Automatic Partitioning
    │
    ├──────────────┬──────────────┐
    ▼              ▼              ▼
Partition 0    Partition 1    Partition N
    │              │              │
    ▼              ▼              ▼
Cross-FPGA Interface / Cycle Control / Scan Dump
    │              │              │
    └──────────────┼──────────────┘
                   ▼
          Multi-FPGA Runtime
                   │
        ┌──────────┴──────────┐
        ▼                     ▼
   Cycle-accurate Run    Global Pause
                              │
                              ▼
                      Distributed Dump
                              │
                              ▼

                              │
                       Restore / Replay
                              │
                              ▼

```

#### 1.1.3 现有技术的能力边界与研究空缺

- 多FPGA原型验证已经具备较成熟的电路划分、跨片接口和高速互连技术，可以解决“大规模设计如何部署和运行”的问题，但完整状态提取、一致暂停和确定性重放通常不是其核心能力。
- 基于Scan Dump的FPGA仿真可以通过暂停、状态扫描、Snapshot恢复和重新执行获得较强的可观察性，但已有机制主要面向单FPGA，受单片容量限制。
- 将两类技术结合后，单FPGA中的集中式状态管理转化为多FPGA中的分布式状态一致性问题，需要同时解决周期精确运行、全局一致暂停、状态聚合、恢复和重放。
- 因此，本课题关注的研究空缺是：如何在保留多FPGA规模扩展能力的同时，引入完整的仿真调试语义。

| 单FPGA Scan Dump仿真 | 受单FPGA容量限制 | 核心能力 | 核心能力 | 核心能力 | 核心能力 |

#### 1.1.4 本课题研究目标：可运行、可暂停、可观测、可重放的多FPGA仿真系统

本课题面向大规模SoC验证，在多FPGA原型验证基础上引入基于Scan Dump的完整状态管理机制，研究周期精确、可扩展、可重放的多FPGA硬件仿真方法。

系统的核心能力包括：

- **可运行（Run）**：将大规模RTL设计划分并部署到多个FPGA，保持原始逻辑行为并进行周期精确执行。
- **可暂停（Pause）**：所有FPGA在统一DUT逻辑周期边界共同停止，形成稳定快照点。
- **可观测（Dump/Observe）**：通过分布式Scan Dump提取各FPGA时序状态，组合形成全局Snapshot。
- **可恢复（Restore）**：将Snapshot按状态映射写回各FPGA，使系统恢复到指定逻辑周期。
- **可重放（Replay）**：从Snapshot恢复后确定性重执行DUT，重新获得目标时间段的内部波形。

SMART采用“逻辑统一、物理解耦”的总体设计思想：

- **逻辑统一**：多个FPGA共同构成具有统一DUT逻辑时钟、运行状态和Snapshot语义的仿真系统。
- **物理解耦**：通过统一的数据与控制抽象，屏蔽FPGA型号、板卡、物理链路和服务器拓扑差异。
- **流程自动化**：从RTL输入开始，自动完成电路划分、仿真结构集成和多FPGA部署，降低新DUT接入成本。

### 1.2 多FPGA周期精确执行与一致暂停

#### 1.2.1 跨FPGA周期精确执行机制

- 将DUT逻辑时钟与FPGA物理时钟解耦，由统一的周期推进机制控制各分区执行。
- 当前逻辑周期内的跨分区数据全部完成传播后，各FPGA共同推进下一DUT周期。
- 对连续跨越多个分区的组合路径，根据实际传播关系完成多轮跨片数据交换，保证划分前后的逻辑行为一致。

#### 1.2.2 LI-TDM跨边界接口与统一周期控制

- 使用LI-TDM封装跨分区信号，通过时分复用降低物理链路数量需求。
- 将LI-TDM的跨片传输状态与DUT周期推进结合，保证跨片数据传输完成后再更新时序状态。
- 统一跨边界接口和时钟控制，为后续Pause和Scan Dump提供一致的运行语义。

#### 1.2.3 多FPGA一致暂停机制

- Pause请求不直接停止单个FPGA，而是在统一DUT逻辑周期边界生效。
- 各分区完成当前周期计算和跨片数据交换后进入暂停状态，保证所有FPGA对应同一全局逻辑周期。
- 统一Run、Step、Pause等控制语义，为后续全局Snapshot提供稳定状态点。

#### 1.2.4 Cosim阶段性验证

- 在逻辑仿真环境中实例化多个划分子设计，模拟跨FPGA通信和周期推进过程。
- 验证Run、Step、Pause等控制操作，以及多分区在复杂跨片传播条件下的周期一致性。
- 通过Cosim提前验证控制逻辑，减少真实多FPGA上板后的系统级调试成本。

### 1.3 分布式状态提取、恢复与重放

#### 1.3.1 Scan Dump结构集成

- 在各划分子设计中插入扫描链，将分布在不同FPGA中的时序状态转化为可导出、可恢复的状态数据。
- 建立原始DUT状态与各FPGA局部扫描状态之间的映射关系。
- 将扫描链控制与周期推进控制统一，使状态提取仅在全局一致暂停后进行。

#### 1.3.2 分布式状态提取与Global Snapshot

- 各FPGA在同一逻辑周期暂停后分别执行Scan Dump，导出本地时序状态。
- 汇聚各节点状态，并根据状态映射重建完整Global Snapshot。
- 验证多FPGA状态组合后与原始DUT对应逻辑周期的状态一致性。

#### 1.3.3 状态恢复与确定性重放

- 将Global Snapshot拆分并写回对应FPGA，实现分布式状态恢复。
- 从恢复后的逻辑周期重新执行DUT，通过确定性重放恢复目标时间段的内部行为。
- 结合逻辑仿真或状态追踪生成内部波形，为长周期问题定位提供调试能力。
- 中期阶段重点完成状态提取链路，状态恢复与完整重放流程继续完善。

#### 1.3.4 阶段性验证结果

- 验证一致暂停后各FPGA局部状态的正确导出。
- 检查状态映射和Global Snapshot聚合的正确性。
- 记录Scan Dump的数据规模、导出时间和相关资源开销，为后续性能优化提供依据。

### 1.4 面向多FPGA仿真的自动化电路划分

#### 1.4.1 自适应粒度划分

- 根据设计层次结构和模块资源规模递归展开RTL层次。
- 对资源规模适中的模块保留层次，以模块为划分单元；对过大模块继续展开，必要时下降到网表级。
- 在模块级和网表级之间自适应选择划分粒度，兼顾划分质量和处理复杂度。

#### 1.4.2 超图建模与划分

- 将模块或网表实例建模为超图节点，并基于资源评估结果设置节点权重。
- 将RTL连接建模为超边，结合连接位宽描述跨分区通信开销。
- 调用超图划分算法，在资源约束下优化资源平衡和Cut Size。

#### 1.4.3 RTL分区生成与PPD分析

- 根据划分结果重新组织RTL，将同一分区的实例打包为独立子设计。
- 保留跨分区连接信息，为后续LI-TDM接口插入提供输入。
- 分析划分后的分区传播深度PPD，评估一个逻辑周期所需的跨片通信轮次。

#### 1.4.4 阶段性实验结果

- 选取不同规模和层次结构的Benchmark与RISC-V设计进行划分实验。
- 评估资源平衡、Cut Size、PPD和算法运行时间。
- 对比模块级、网表级和自适应粒度划分结果，分析不同粒度对划分质量的影响。

### 1.5 可扩展的多FPGA运行控制与状态传输

#### 1.5.1 Fabric Topology与通信抽象

- 将不同FPGA节点及物理链路组织为统一Fabric Topology。
- 使用统一流式接口抽象PCIe、QSFP/Aurora、Ethernet等物理信道，降低上层仿真逻辑与硬件平台的耦合。
- 支持从双FPGA直连逐步扩展到多节点和跨服务器拓扑。

#### 1.5.2 统一控制平面

- 由Host通过统一入口管理多FPGA运行状态。
- 分发Run、Pause、Step、Reset、Dump、Restore等控制命令，并保证周期相关操作在一致逻辑边界生效。
- 将多物理节点抽象为单一逻辑仿真器，简化用户侧控制流程。

#### 1.5.3 分布式状态传输

- 建立各FPGA到Host的状态汇聚路径，用于收集Scan Dump数据并形成Global Snapshot。
- 恢复时沿相反路径将状态重新分发到对应节点。
- 复用现有多FPGA互连构建可扩展的状态传输路径，降低对主机直连接口数量的依赖。

#### 1.5.4 阶段性实现

- 完成双FPGA数据与控制通路的基本实现。
- 完成Fabric Topology和相关运行时组件开发。
- 验证统一控制入口、跨节点命令传输和状态数据传输，为后续四FPGA扩展提供基础。

### 1.6 双FPGA仿真加速原型系统与阶段性实验

#### 1.6.1 实验平台与系统结构

- 运行裸机程序，验证多FPGA系统能够保持稳定、周期精确的执行过程。

#### 1.6.3 可暂停与可观测能力验证

- 验证Run、Step、Pause等控制功能以及双FPGA的一致暂停。
- 在暂停点导出各FPGA局部状态，并聚合为Global Snapshot。
- 对比状态和运行结果，验证跨FPGA状态提取的正确性。

#### 1.6.4 阶段性系统结果
