# 中期报告大纲

## 第一章 课题研究进展与阶段性成果

### 1.1 研究目标与总体技术路线回顾

#### 1.1.1 多 FPGA 仿真加速的背景与意义

- 随着现代 SoC 规模和复杂度持续提升，处理器核、缓存层次、片上互连、专用加速器和外设等模块不断增加，系统级验证需要覆盖更复杂的硬件状态空间以及更长时间的软件执行过程。
- 传统 RTL 软件逻辑仿真具有可观察性强、调试灵活等优势，但在大规模 SoC、长时间软件负载、操作系统和应用程序验证场景下，执行速度成为限制验证效率的重要因素。
- FPGA 仿真加速通过将待验证 RTL 映射到可编程逻辑上运行，在保留硬件执行语义的同时显著提高仿真速度，使较长时间的软件工作负载和软硬件协同验证成为可能。
- 随着待验证设计规模继续增长，单片 FPGA 的逻辑、存储和片上互连资源逐渐成为容量瓶颈。将大规模设计划分并部署到多个 FPGA 上，可以进一步扩展仿真系统的可承载规模。
- 多 FPGA 仿真并非简单叠加多个 FPGA 的资源。原本位于同一同步数字系统中的模块被分布到多个物理节点后，片内连接转化为跨 FPGA 通信，原始设计中的组合传播和时钟推进需要通过跨片数据交换来维持。
- 因此，多 FPGA 仿真加速在扩展系统容量的同时，也引入了电路划分、跨片通信、周期同步、状态一致性以及分布式运行控制等新的技术问题。

#### 1.1.2 多 FPGA 仿真加速面临的关键问题

**（1）高质量、自动化的多 FPGA 电路划分**

- 多 FPGA 部署首先需要将原始设计划分为多个能够分别映射到目标 FPGA 的分区，并满足各 FPGA 的逻辑、存储和互连资源约束。
- 划分结果不仅需要保证资源使用均衡，还需要控制跨分区通信开销。割边数量（Cut Size）决定需要经过跨 FPGA 链路传输的数据规模，是影响跨片通信带宽需求的重要指标。
- 除通信数据量外，组合逻辑在多个分区之间的传播深度也会影响一个 DUT 逻辑周期的执行时间。当一条组合传播路径连续跨越多个分区时，系统需要经过多轮跨片数据交换才能完成该逻辑周期的计算。因此，分区传播深度（Partition Propagation Depth，PPD）直接影响逻辑时钟推进所需的通信轮次。
- 资源平衡、Cut Size、PPD 与划分粒度之间相互制约。过粗的划分可能导致资源超限或负载不均衡，过细的划分则可能增加跨分区通信量和传播深度。
- 对不同层次结构和不同规模的 DUT，划分流程还需要尽可能减少人工指定边界和手工修改设计的过程，使多 FPGA 部署能够面向通用 RTL 设计自动完成。

**（2）周期精确执行与全局状态一致性**

- 原始同步 RTL 设计在统一的逻辑时钟模型下执行，一个逻辑周期内完成组合逻辑传播，并在时钟边沿统一更新时序状态。
- 设计被划分到多个 FPGA 后，跨分区信号需要经过 QSFP、PCIe、Ethernet 等物理链路传输，其传播延迟和带宽特性与原始片内连线显著不同。因此，FPGA 的物理运行时钟不能直接等同于 DUT 的逻辑时钟。
- 多 FPGA 仿真系统需要在当前逻辑周期相关的跨片数据完成传播、各分区满足推进条件后，再共同进入下一逻辑周期，从而使多个物理 FPGA 对外表现为一个周期精确的统一仿真系统。
- 周期一致性不仅决定正常运行时的功能正确性，也决定暂停和状态获取的正确性。系统暂停时，各 FPGA 必须对应于同一个 DUT 逻辑周期，否则多个节点导出的状态无法组成原始 RTL 在任一真实执行时刻的全局状态。
- 对于基于 Scan Dump 的状态捕获和重放机制，全局一致的暂停点是正确恢复系统状态、生成波形并进行确定性重放的基础。因此，多 FPGA 系统需要同时解决同步执行与同步暂停问题。

**（3）可扩展、可移植的多 FPGA 系统架构**

- 多 FPGA 仿真平台可能由不同型号的 FPGA 板卡、不同数量的计算节点以及不同的物理通信链路组成，系统规模还可能从单服务器扩展到跨服务器部署。
- 在数据平面上，片内互连、QSFP、PCIe、Ethernet 等物理通道具有不同的协议、延迟和带宽特征。上层仿真逻辑需要通过统一的通信抽象屏蔽这些物理差异，避免 DUT 和仿真框架与特定硬件链路紧密耦合。
- 在控制平面上，随着 FPGA 数量增加，逐个节点直接连接主机并进行独立控制会限制系统规模。多个 FPGA 节点需要被组织成一个统一的仿真系统，并通过统一的控制入口完成启动、暂停、步进、状态获取等操作。
- 因此，多 FPGA 仿真系统不仅需要支持更多 FPGA，还需要建立能够跨板卡、跨链路和跨服务器扩展的数据与控制架构，使不同物理部署形式对上层用户表现为统一的硬件仿真器。

#### 1.1.3 现有多 FPGA 仿真方法的局限

- 现有研究已经从电路划分、跨 FPGA 通信和系统部署等角度提出了多种多 FPGA 仿真与原型验证方案，但不同方案通常针对部分问题进行优化，在自动化程度、周期精确性、调试能力以及平台通用性之间仍存在权衡。
- 在电路划分方面，已有方案分别采用网表级、模块级或人工指导的划分方法。固定粒度的划分方法难以同时适应不同规模和不同层次结构的设计，而需要人工指定边界的方案又会增加新 DUT 的部署成本。
- 在运行控制与调试方面，部分 FPGA 原型验证系统主要关注运行性能和容量扩展，对跨 FPGA 逻辑周期的精确控制、全系统同步暂停以及完整内部状态获取的支持有限，使其难以直接提供确定性状态恢复和波形重放能力。
- 在系统通用性和扩展性方面，部分方案依赖特定 FPGA 平台、特定云环境、固定物理链路或同构互连结构，导致系统迁移到其他硬件平台或扩展到更多 FPGA、更多服务器时需要重新设计通信和控制结构。
- 因此，现有多 FPGA 硬件仿真方法在自动化划分、周期精确执行、完整调试能力和跨平台扩展性之间仍存在明显权衡，需要进一步研究能够统一处理上述问题的多 FPGA 仿真框架。

#### 1.1.4 本课题总体研究目标

本课题面向大规模 SoC 验证，研究一种周期精确、可扩展、可重放的多 FPGA 硬件仿真方法，在利用多个 FPGA 扩展仿真容量和运行性能的同时，保留逻辑仿真中确定的状态演化过程以及较强的状态观察和调试能力。

- **逻辑统一**：多个物理 FPGA 节点共同构成一个统一的逻辑仿真系统，保持原始 RTL 的逻辑周期和状态演化语义，并通过统一的控制入口完成系统运行、暂停和状态管理。
- **物理解耦**：将上层仿真逻辑与 FPGA 数量、板卡类型、物理通信链路及服务器拓扑解耦，使相同的 DUT 和仿真机制能够适配不同层次、不同规模的物理部署环境。
- **流程自动化**：形成从 RTL 输入、电路划分、结构集成和多 FPGA 部署，到运行控制、状态获取、恢复和波形重放的一体化流程，降低将新设计部署到多 FPGA 仿真平台上的人工成本。
- 上述目标分别对应后续在电路划分、周期精确仿真与状态重放、多 FPGA 通信及运行时系统等方面开展的研究工作。

#### 1.1.5 中期阶段目标

- 完成多 FPGA 仿真核心组件的阶段性开发与验证，包括自动化电路划分、Cosim 仿真环境以及 Fabric Topology 等组件。
- 构建双 FPGA 原型系统，完成基本的数据通路、控制通路和同步运行机制集成。
- 以 PicoRV32 等小型 RISC-V 设计作为基础验证对象，并逐步面向更大规模处理器设计验证系统的划分、运行、暂停和状态重放能力。
- 在上述阶段性成果的基础上，进一步开展多 FPGA 规模扩展、大规模 SoC 部署和系统性能优化。
