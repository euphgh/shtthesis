# 中期报告大纲

## 第一章 课题研究进展与阶段性成果

### 1.1 研究目标与总体技术路线回顾

#### 1.1.1 从多 FPGA 原型验证到可观测的多 FPGA 仿真加速

- 随着现代 SoC 规模和复杂度持续提升，系统级验证不仅需要覆盖更大的硬件状态空间，还需要运行固件、操作系统和应用程序等长时间软件负载。传统 RTL 软件逻辑仿真具有较强的可观察性和调试能力，但执行速度难以高效支撑大规模、长时间的软件运行场景。
- FPGA 原型验证通过将 RTL 设计映射到可编程逻辑上直接运行，可以显著提高执行速度。当设计规模超过单片 FPGA 的逻辑、存储和片上互连资源后，通常进一步采用电路划分与跨片互连，将原始设计部署到多个 FPGA 上，从而扩展可承载的设计规模。
- 传统多 FPGA 原型验证的核心目标是让超出单 FPGA 容量的设计能够正确、高速地运行，其主要能力集中在大规模部署、跨片通信和运行性能。相比之下，软件逻辑仿真所具有的任意时刻暂停、完整状态观察和问题复现能力，在多 FPGA 原型系统中仍然受到明显限制。
- 原型系统中的 DUT 状态实际分布在 FPGA 内部大量时序器件中，常规 Trace 或片上逻辑分析方法通常只能选择有限的观测信号，并受到片上存储资源和观测窗口长度限制。对于长时间运行后出现的问题，难以像软件逻辑仿真一样重新获得目标时刻完整的内部状态和波形。
- 基于 Scan Dump 的硬件仿真方法为状态观测提供了另一种思路：在确定的逻辑周期暂停 DUT，将时序器件中的完整状态导出形成 Snapshot，并在需要时恢复该状态，通过确定性重新执行重新生成目标时间段内的内部波形。
- 当 Scan Dump 从单 FPGA 扩展到多 FPGA 环境后，状态捕获的对象不再是单个芯片，而是分布在多个物理 FPGA 上的全局 DUT 状态。只有所有 FPGA 在同一个 DUT 逻辑周期一致暂停，并正确提取和组合各节点的状态，才能获得与原始 RTL 执行过程一致的 Snapshot。
- 因此，本课题研究的核心不是单纯构建一个更大规模的多 FPGA 原型验证平台，而是在多 FPGA 原型验证的基础上引入周期精确的暂停、分布式全状态提取、状态恢复和确定性重放能力，使系统从“能够运行”进一步发展为“能够暂停、能够观测、能够恢复、能够重放”的多 FPGA 硬件仿真加速系统。

多 FPGA 原型验证与本课题所面向的多 FPGA 仿真加速在能力侧重点上存在如下区别：

| 能力 | 多 FPGA 原型验证 | 基于 Scan Dump 的多 FPGA 仿真加速 |
| --- | --- | --- |
| 大规模 RTL 部署 | 支持 | 支持 |
| 高速运行软件负载 | 支持 | 支持 |
| 跨 FPGA 周期精确执行 | 以保证功能运行正确为目标 | 作为暂停、状态提取和重放的基础能力 |
| 全系统一致暂停 | 通常不是核心能力 | 核心能力 |
| 完整时序状态提取 | 能力有限 | 核心能力 |
| Snapshot / Restore | 能力有限 | 核心能力 |
| 确定性重放与波形恢复 | 能力有限 | 核心能力 |

#### 1.1.2 多 FPGA 状态提取与可重放仿真的关键问题

**（1）分布式状态的一致暂停与全局提取**

- 在单 FPGA Scan Dump 系统中，DUT 的时序状态集中在同一物理 FPGA 内，系统暂停后可以直接扫描并导出这些状态。
- 当 DUT 被划分到多个 FPGA 后，原始设计中的寄存器、存储状态及其他时序状态被分散到不同物理节点。此时一个完整 Snapshot 不再对应某一片 FPGA 的状态，而是所有 FPGA 在同一个 DUT 逻辑周期上的状态集合。
- 若不同 FPGA 停止在不同逻辑周期，即使各节点分别能够正确完成 Scan Dump，最终组合得到的状态也不对应原始 RTL 在任一真实执行时刻的全局状态，无法用于正确恢复和重放。
- 因此，多 FPGA Scan Dump 首先要求系统具备全局周期一致暂停能力：所有节点必须在同一 DUT 逻辑周期完成当前计算并进入稳定状态后共同停止。
- 一致暂停后，各 FPGA 分别导出属于自身分区的时序状态，系统再根据原始 DUT 的状态映射关系进行聚合，形成完整的全局 Snapshot。
- 分布式状态的“一致暂停—局部导出—全局聚合”构成多 FPGA 可观测仿真的核心状态提取流程。

```text
         DUT logical cycle N
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
     FPGA 0    FPGA 1    FPGA N
        │         │         │
        └── Global Pause ───┘
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
      Dump 0    Dump 1    Dump N
        └─────────┼─────────┘
                  ▼
          Global Snapshot
```

**（2）跨 FPGA 执行过程的周期精确性**

- 原始同步 RTL 设计在统一的逻辑时钟模型下运行，一个逻辑周期内完成组合逻辑传播，并在时钟边沿统一更新时序状态。
- 设计被划分到多个 FPGA 后，原本的片内组合传播路径可能跨越多个分区，跨分区信号需要经过实际物理链路传输。FPGA 的物理运行时钟因此不能直接等同于 DUT 的逻辑时钟。
- 多 FPGA 仿真系统需要在当前 DUT Cycle 所需的跨分区数据全部传播完成后，再统一推进下一逻辑周期。周期精确执行既是保证功能正确性的基础，也是定义全局一致暂停点的前提。
- 对于连续跨越多个分区的组合路径，一个 DUT Cycle 内可能需要经历多轮跨 FPGA 数据交换。分区传播深度（Partition Propagation Depth，PPD）刻画了这类跨分区传播层次，并直接影响一个逻辑周期完成所需的通信轮次和仿真性能。
- 因此，跨 FPGA 周期精确执行不仅需要解决节点间同步问题，还需要与电路划分、跨片通信和逻辑周期推进机制协同设计。

**（3）多 FPGA 状态传输、恢复与统一控制**

- 多 FPGA 仿真系统的控制对象不仅包括 DUT 的启动和复位，还包括 Pause、Step、Dump、Restore、Replay 等与状态管理相关的操作。
- 随着 FPGA 数量增加，主机直接连接并独立控制每个节点会限制系统规模。控制命令需要能够从统一入口分发到各 FPGA，并保证涉及状态变化的操作在一致的逻辑周期边界生效。
- Scan Dump 产生的状态数据分布在多个 FPGA 上，系统需要建立可扩展的数据汇聚路径，将各节点状态传输至主机形成全局 Snapshot；恢复时则需要执行相反过程，将全局状态重新分发到对应 FPGA。
- 因此，多 FPGA 仿真系统需要同时构建统一的控制平面和状态传输路径，使多个物理节点在用户视角下表现为一个能够统一运行、暂停、导出状态和恢复状态的仿真器。

**（4）面向多 FPGA 仿真的高质量自动化电路划分**

- 多 FPGA 仿真首先需要将超出单 FPGA 容量的 RTL 设计划分为多个可部署分区，并满足各目标 FPGA 的资源约束。
- 划分结果不仅影响资源平衡和跨片通信量，还会影响 PPD，从而进一步影响周期精确仿真的性能。
- 划分粒度同样会影响划分质量。不同粒度下，划分对象数量、资源估计方式、模块边界、Cut Size 和 PPD 均可能发生变化。
- 对于面向通用 RTL 设计的多 FPGA 仿真系统，划分过程还应尽量减少人工指定划分边界和针对具体 DUT 的手工修改，使不同规模和层次结构的设计能够通过统一流程完成资源分析、划分和子设计生成。
- 因此，多 FPGA 仿真的电路划分需要在资源平衡、Cut Size、PPD、划分粒度和自动化程度等多个方面进行综合权衡，划分质量将直接影响后续跨 FPGA 通信以及周期精确仿真的运行性能。

其处理过程可概括为：

```text
RTL Design
    │
    ▼
Automatic Partitioning
    │
    ├──────────────┬──────────────┐
    ▼              ▼              ▼
Partition 0    Partition 1    Partition N
    │              │              │
    ▼              ▼              ▼
Cross-FPGA Interface / Cycle Control / Scan Dump
    │              │              │
    └──────────────┼──────────────┘
                   ▼
          Multi-FPGA Runtime
                   │
        ┌──────────┴──────────┐
        ▼                     ▼
   Cycle-accurate Run    Global Pause
                              │
                              ▼
                      Distributed Dump
                              │
                              ▼
                          Snapshot
                              │
                       Restore / Replay
                              │
                              ▼
                           Waveform
```

#### 1.1.3 现有技术的能力边界与研究空缺

- 多 FPGA 原型验证已经形成了较成熟的大规模电路部署技术，通过电路划分、跨片接口和高速互连，可以将超出单 FPGA 容量的设计映射到多个 FPGA 上运行。其主要目标是扩展系统容量并保持较高执行性能。
- 这类系统通常将 FPGA 作为目标运行平台，调试主要依赖预先选择的 Trace 信号、片上逻辑分析仪或有限的运行日志。对于完整内部状态的任意周期提取、跨 FPGA 一致暂停以及基于完整状态的确定性重放，支持相对有限。
- 另一方面，基于 Scan Dump 的 FPGA 仿真方法能够通过暂停 DUT、扫描时序状态、恢复 Snapshot 和重新执行，实现接近软件逻辑仿真的状态观察和波形重放能力。但当这一机制扩展到多 FPGA 系统后，原本集中在单片 FPGA 内的状态管理问题转化为分布式状态一致性问题。
- 多 FPGA 原型验证解决了“大规模设计如何部署和运行”的问题，Scan Dump 仿真解决了“运行中的设计如何暂停、观察和重放”的问题。本课题关注两类技术结合后产生的新问题，即如何使分布在多个 FPGA 上的大规模 DUT 同时具备周期精确运行、全局一致暂停、完整状态提取和确定性重放能力。
- 在此基础上，电路划分、跨片通信和系统控制也需要围绕“可暂停、可提取、可恢复”的仿真语义重新组织，而不能仅以原型验证中的高速运行为目标。

上述研究空缺可以概括为：

| 技术方向 | 多 FPGA 扩展 | 周期一致暂停 | 完整状态提取 | 状态恢复 | 确定性重放 |
| --- | --- | --- | --- | --- | --- |
| 多 FPGA 原型验证 | 核心能力 | 非核心能力 | 非核心能力 | 非核心能力 | 非核心能力 |
| 单 FPGA Scan Dump 仿真 | 受单 FPGA 容量限制 | 核心能力 | 核心能力 | 核心能力 | 核心能力 |
| 本课题 | 核心能力 | 核心能力 | 核心能力 | 核心能力 | 核心能力 |

#### 1.1.4 本课题研究目标：可运行、可暂停、可观测、可重放的多 FPGA 仿真系统

本课题面向大规模 SoC 验证，在多 FPGA 原型验证技术的基础上引入基于 Scan Dump 的完整状态管理机制，研究一种周期精确、可扩展、可重放的多 FPGA 硬件仿真方法。系统不仅需要将超出单 FPGA 容量的 RTL 设计部署到多个 FPGA 上运行，还需要在指定逻辑周期实现全局一致暂停，提取分布在多个 FPGA 上的完整时序状态，并通过状态恢复和确定性重新执行获得目标执行区间的内部波形。

系统的核心能力包括：

- **可运行（Run）**：将大规模 RTL 设计划分并部署到多个 FPGA，在保持原始逻辑行为的前提下进行周期精确执行。
- **可暂停（Pause）**：所有 FPGA 在统一的 DUT 逻辑周期边界达到一致状态并共同停止，为全局状态提取提供稳定快照点。
- **可观测（Dump / Observe）**：通过分布式 Scan Dump 提取各 FPGA 中的时序状态，组合形成完整全局 Snapshot，突破有限 Trace 信号带来的内部状态观测限制。
- **可恢复（Restore）**：将保存的全局 Snapshot 按状态映射重新写回各 FPGA，使系统恢复到指定逻辑周期的完整执行状态。
- **可重放（Replay）**：从恢复后的 Snapshot 确定性重新执行 DUT，并结合逻辑仿真或状态追踪机制恢复目标时间段内的内部波形，用于问题定位和调试。

为实现上述能力，SMART 采用“逻辑统一、物理解耦”的总体设计思想：

- **逻辑统一**：多个物理 FPGA 共同构成一个具有统一 DUT 逻辑时钟、统一运行状态和统一 Snapshot 语义的仿真系统。
- **物理解耦**：跨 FPGA 仿真逻辑尽量与具体 FPGA 型号、板卡、物理链路和服务器拓扑解耦，通过统一的数据和控制抽象适配不同部署环境。
- **流程自动化**：从 RTL 输入开始，自动完成电路划分、仿真结构集成和多 FPGA 部署，降低将新 DUT 接入仿真系统所需的人工工作。

SMART 的总体技术路线围绕“设计部署—周期精确运行—全局暂停—状态提取—恢复重放”构建：

中期阶段围绕上述技术链路已经开展以下工作：

- 自动化电路划分流程：完成层次结构分析、资源建模、超图划分及 PPD 分析等核心功能，为大规模 RTL 自动部署到多个 FPGA 提供基础。
- Cosim 仿真环境：在真实多 FPGA 上板之前验证跨分区通信、周期推进、暂停控制及多节点协同行为，降低系统级调试成本。
- Fabric Topology 与运行时组件：建立多个 FPGA 节点之间的数据与控制通路，为统一 Pause、Dump、Restore 等操作提供可扩展的通信基础。
- 双 FPGA 原型系统：以 PicoRV32 等小型 RISC-V 设计为验证对象，集成划分、跨片通信、周期同步和状态管理机制，验证从“多 FPGA 运行”进一步扩展到“一致暂停与状态提取”的可行性。
- 后续工作将在双 FPGA 系统基础上进一步扩大 FPGA 数量和 DUT 规模，并完善状态恢复、确定性重放、完整波形获取以及系统性能评估。
