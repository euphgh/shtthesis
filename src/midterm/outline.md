# 中期报告大纲

## 第一章 课题研究进展与阶段性成果

### 1.1 研究目标与总体技术路线回顾

#### 1.1.1 多 FPGA 仿真加速的背景与意义

- 现代 SoC 规模和复杂度持续提升，处理器核、缓存层次、片上互连、专用加速器和外设等模块不断增加，使得系统级验证的复杂度和验证周期明显增长。
- 传统 RTL 软件逻辑仿真可观察性强、调试方便，但在大规模 SoC、长时间软件负载、操作系统和应用程序验证场景下，仿真速度较低，运行时间成为验证效率的主要瓶颈。
- 提出 FPGA 仿真加速：FPGA 能够将待验证的 RTL 设计映射到真实可编程逻辑中执行，相比纯软件逻辑仿真具有明显的性能优势，因此被广泛应用于处理器、SoC 和软硬件协同验证。
- FPGA 仿真加速虽然能够显著提高执行速度，但单片 FPGA 的逻辑、存储和互连资源仍然有限。
- 提出多 FPGA 仿真加速：将一个大规模设计进行划分并部署到多个 FPGA 上，虽然能扩展容量，但原本位于同一芯片、同一同步逻辑系统中的模块被划分后，原本的片内信号需要经过 FPGA 之间的物理链路传输。
- 原始 RTL 设计通常假定各模块在统一的逻辑时钟模型下运行，而多 FPGA 系统中的物理通信存在额外延迟和带宽限制。因此，多 FPGA 部署实际上改变了原始设计的物理执行方式，需要通过额外机制维持原始 RTL 的逻辑行为。

#### 1.1.2 多 FPGA 仿真加速的核心技术挑战

**（1）电路规模与 FPGA 容量之间的矛盾**

- 多 FPGA 部署首先需要对原始设计进行划分。
- 过粗的划分可能造成部分 FPGA 资源超限或资源利用不均衡；过细的网表级划分则可能产生大量跨 FPGA 信号，显著增加跨片通信压力。
- 此外另一个概念"分区传播深度"也会影响仿真一个逻辑时钟周期所花费的具体时间，划分算法需要对其有优化
- 划分粒度、资源平衡程度、割边数量、分区传播深度之间存在明显权衡。
- 传统多 FPGA 划分流程往往需要设计人员根据具体 DUT 和硬件平台进行较多人工干预。
- 因而需要解决如何在满足 FPGA 资源约束的同时降低跨片通信开销，并提高划分和部署流程的自动化程度。

**（2）逻辑同步与物理通信之间的矛盾**

- 原始同步 RTL 设计通常假设一个逻辑周期内组合逻辑能够完成传播，并在统一时钟边沿更新状态。
- 将设计划分到多个 FPGA 后，跨片信号需要经过 QSFP、PCIe、Ethernet 等实际物理链路传输，其延迟和带宽特性与原始片内连线存在显著差异。
- 作为周期精确的Emulation系统，如何在物理上分布的 FPGA 节点之间维持统一、确定的逻辑时钟语义，是保证多 FPGA 仿真结果与原始 RTL 行为一致的关键问题。
- 特别是在基于Scandump的仿真加速技术中，要求多FPGA系统能够精确地暂停在同一个Cycle中，否则导出的内部状态与RTL不一致。
- 需要解决在有物理延迟的多 FPGA 系统中，如何实现同步的仿真和暂停。

**（3）系统扩展性与平台耦合问题**

- 多 FPGA 系统可能运行在不同板卡、不同服务器以及不同物理通信链路之上。
- 现有部分方案依赖特定 FPGA 平台、特定高速互连或固定主机通信结构，使得系统难以迁移到新的硬件平台，或者难以从双 FPGA 系统进一步扩展到更大规模。
- 因而需要考虑如何将上层仿真逻辑和底层物理通信机制解耦，为不同层次和不同类型的物理互连提供统一通信和控制抽象。
- 从系统可扩展性上而言，如何将异构的多 FPGA 抽象成一个仿真加速系统，并使用单一节点进行控制。也是一个系统难题。

#### 1.1.3 现有多 FPGA 仿真方案的不足

- 现有研究通常能够针对多 FPGA 仿真中的某一个或若干问题提出有效方案，但在自动化程度、可调试性、平台通用性和系统扩展性之间仍存在明显权衡。
- 在自动化方面，部分方案仍需要人工指定划分边界、手工修改 RTL 或根据具体平台调整部署流程。
- 在可调试性方面，一些高性能 FPGA 原型验证方案更关注运行速度和系统容量，但在周期精确的运行和暂停上依然有缺陷，内部状态获取能力也有限，难以提供完整状态捕获和确定性重放能力。
- 在通用性和扩展性方面，部分系统依赖特定云平台、特定物理链路或同构的 FPGA 互连方式，导致其跨平台迁移和规模扩展能力受到限制。

#### 1.1.5 本课题总体研究目标

本课题旨在构建一种面向大规模 SoC 的多 FPGA 硬件仿真方法，在利用多个 FPGA 扩展仿真容量和运行性能的同时，尽可能保留软件逻辑仿真的确定性、可观察性与可调试性。

- 从逻辑上看，多个 FPGA 节点应共同表现为一个统一、确定的仿真系统。它在保持原始 RTL 设计的逻辑周期和状态演化语义的同时，被单一的节点控制。
- 从物理上看，框架应尽量屏蔽 FPGA 数量、板卡类型和底层通信链路等差异，降低 DUT 与具体硬件平台之间的耦合。
- 最终目标是形成从 RTL 输入、电路划分、结构集成、多 FPGA 部署，到运行控制、状态获取和波形重放的一体化流程。
