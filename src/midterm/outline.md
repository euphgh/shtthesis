#### 1.1.1 FPGA 仿真加速的背景与意义

建议篇幅约 300～400 字。

- 从现代 SoC 规模和复杂度持续提升的背景切入，说明处理器核、缓存层次、片上互连、专用加速器和外设等模块不断增加，使得系统级验证的复杂度和验证周期明显增长。
- 指出传统 RTL 软件逻辑仿真的优势是可观察性强、调试方便，但在大规模 SoC、长时间软件负载、操作系统和应用程序验证场景下，仿真速度较低，运行时间可能成为验证效率的主要瓶颈。
- 引出 FPGA 仿真加速。FPGA 能够将待验证的 RTL 设计映射到真实可编程逻辑中执行，相比纯软件逻辑仿真具有明显的性能优势，因此被广泛应用于处理器、SoC 和软硬件协同验证。
- 强调 FPGA 仿真加速的价值不仅是提高执行速度，还在于能够承载较长时间的软件工作负载，使操作系统、驱动程序和应用程序能够在接近真实硬件的执行模型上运行，为系统级验证提供基础。
- 本段不需要详细展开 FPGA Prototype、Emulation 等概念差异，重点是建立“为什么需要 FPGA 仿真加速”的背景。

#### 1.1.2 从单 FPGA 到多 FPGA 仿真加速

建议篇幅约 200～300 字。

- 说明 FPGA 仿真加速虽然能够显著提高执行速度，但单片 FPGA 的逻辑、存储和互连资源仍然有限。
- 随着待验证设计规模继续增长，即使使用 VU37P 等大容量 FPGA，复杂 CPU、多核 SoC、GPU/NPU 等设计仍可能超出单 FPGA 的资源容量。
- 因此，将一个大规模设计进行划分并部署到多个 FPGA 上，是扩展 FPGA 仿真系统容量的一种自然方式。
- 需要强调，多 FPGA 系统并不是简单增加 FPGA 数量。原本位于同一芯片、同一同步逻辑系统中的模块被划分后，原本的片内信号需要经过 FPGA 之间的物理链路传输。
- 原始 RTL 设计通常假定各模块在统一的逻辑时钟模型下运行，而多 FPGA 系统中的物理通信存在额外延迟和带宽限制。因此，多 FPGA 部署实际上改变了原始设计的物理执行方式，需要通过额外机制维持原始 RTL 的逻辑行为。
- 这一点作为后续“核心技术挑战”的转折。

#### 1.1.3 多 FPGA 仿真加速的核心技术挑战

建议篇幅约 400～600 字，是本节重点。

此处暂时不直接按照本课题最终的三个研究方向进行组织，而是先从领域本身的矛盾和问题出发。后续可以根据实际研究内容进一步调整。

**（1）电路规模与 FPGA 容量之间的矛盾**

- 多 FPGA 部署首先需要对原始设计进行划分。
- 过粗的划分可能造成部分 FPGA 资源超限或资源利用不均衡；过细的网表级划分则可能产生大量跨 FPGA 信号，显著增加跨片通信压力。
- 划分粒度、资源平衡程度以及割边数量之间存在明显权衡。
- 同时，传统多 FPGA 划分流程往往需要设计人员根据具体 DUT 和硬件平台进行较多人工干预。
- 因而需要解决如何在满足 FPGA 资源约束的同时降低跨片通信开销，并提高划分和部署流程的自动化程度。

**（2）逻辑同步与物理通信之间的矛盾**

- 原始同步 RTL 设计通常假设一个逻辑周期内组合逻辑能够完成传播，并在统一时钟边沿更新状态。
- 将设计划分到多个 FPGA 后，跨片信号需要经过 QSFP、PCIe、Ethernet 等实际物理链路传输，其延迟和带宽特性与原始片内连线存在显著差异。
- 因此，DUT 的逻辑时钟不能简单等同于 FPGA 的物理运行时钟。
- 系统必须在跨片数据完成交换、各个划分子设计满足当前逻辑周期的执行条件之后，才能推进下一逻辑周期。
- 如何在物理上分布的 FPGA 节点之间维持统一、确定的逻辑时钟语义，是保证多 FPGA 仿真结果与原始 RTL 行为一致的关键问题。

**（3）性能扩展与可调试性之间的矛盾**

- 软件逻辑仿真的重要优势是内部状态高度可观察，可以方便地记录波形、检查任意内部信号并重复运行。
- FPGA 原型系统虽然运行速度较高，但内部状态的可观察性明显下降，通常只能依赖有限的片上调试资源进行 Trace。
- 当设计进一步分布到多个 FPGA 后，系统状态同时分散在多个物理设备中，长时间运行后出现的问题更加难以精确复现。
- 因此，多 FPGA 仿真系统除了能够正确运行，还需要具备暂停、状态获取、状态恢复和确定性重放等能力，使其在扩展运行性能和容量的同时保留接近逻辑仿真的调试能力。

**（4）系统扩展性与平台耦合问题**

- 多 FPGA 系统可能运行在不同板卡、不同服务器以及不同物理通信链路之上。
- 现有部分方案依赖特定 FPGA 平台、特定高速互连或固定主机通信结构，使得系统难以迁移到新的硬件平台，或者难以从双 FPGA 系统进一步扩展到更大规模。
- 因而需要考虑如何将上层仿真逻辑和底层物理通信机制解耦，为不同层次和不同类型的物理互连提供统一通信和控制抽象。

#### 1.1.4 现有多 FPGA 仿真方案的不足

建议篇幅约 250～350 字。

这一部分用于承接前述技术挑战并引出课题研究目标，表述上应保持客观，避免简单否定已有工作。

核心论点：

- 现有研究通常能够针对多 FPGA 仿真中的某一个或若干问题提出有效方案，但在自动化程度、可调试性、平台通用性和系统扩展性之间仍存在明显权衡。
- 在自动化方面，部分方案仍需要人工指定划分边界、手工修改 RTL 或根据具体平台调整部署流程。
- 在可调试性方面，一些高性能 FPGA 原型验证方案更关注运行速度和系统容量，但内部状态获取能力有限，难以提供完整状态捕获和确定性重放能力。
- 在通用性和扩展性方面，部分系统依赖特定云平台、特定物理链路或同构的 FPGA 互连方式，导致其跨平台迁移和规模扩展能力受到限制。
- 可以用一句总结性的判断收束：

> 因此，现有多 FPGA 硬件仿真系统在系统规模、自动部署、调试能力和平台通用性之间仍存在明显权衡，尚缺少能够同时兼顾上述能力的统一多 FPGA 仿真框架。

后续正式撰写时，需要结合开题报告中的相关工作与参考文献，对上述判断进行文献支撑，避免形成无依据的泛化结论。

#### 1.1.5 本课题总体研究目标

建议篇幅约 200～300 字。

- 在上述背景和问题分析之后，再正式引出 SMART。
- 总体目标可围绕以下表述展开：

> 本课题旨在构建一种面向大规模 SoC 的多 FPGA 硬件仿真方法，在利用多个 FPGA 扩展仿真容量和运行性能的同时，尽可能保留软件逻辑仿真的确定性、可观察性与可调试性。

- SMART 的核心设计思想概括为“逻辑统一、物理解耦”。
- 从逻辑上看，多个物理 FPGA 节点应共同表现为一个统一、确定的仿真系统，保持原始 RTL 设计的逻辑周期和状态演化语义。
- 从物理上看，框架应尽量屏蔽 FPGA 数量、板卡类型和底层通信链路等差异，降低 DUT 与具体硬件平台之间的耦合。
- 最终目标是形成从 RTL 输入、电路划分、结构集成、多 FPGA 部署，到运行控制、状态获取和波形重放的一体化流程。
- 具体研究方向暂不在本节中完全定型，待结合当前已经完成的研究工作进一步细化，再自然过渡到后续各节。
